# 1.9. Воспроизведения общих настроек и зависимости управления от числа кадров

Сохранены [шесть тестов общих настроек](../test/shared_settings_reproduction_test.dart)
и [семь тестов управления камерой](../test/orbit_frame_rate_reproduction_test.dart).
Оба файла включены в preset `all`. Они проверяют **текущее ошибочное поведение**
и проходят, пока ошибки воспроизводятся, как тесты [пункта 1.5](1.5_CAMERA_POSITION_REPRODUCTION.md).
Код библиотеки в пункте 1.9 не меняется. Исправления относятся к фазам 4 и 6;
ожидания тестов нужно заменить вместе с соответствующими исправлениями.

## Общие изменяемые настройки — фаза 6

`final` защищает ссылку глобальной переменной, но не содержимое объекта.
[UniformGroup](../lib/src/core/abstractions.dart) сохраняет значения по ссылке
и возвращает внутреннюю map. [Материалы](../lib/src/core/material.dart) используют
общие blend/stencil presets, [текстуры](../lib/src/core/textures.dart) удерживают
переданный `TextureProperties`. [Цвета и unitNode](../lib/src/misc/example_helper.dart)
также используют общие изменяемые объекты.

| Сценарий | Сейчас | Целевое поведение | Пункт исправления |
| --- | --- | --- | --- |
| Два материала получают `colorWhite`; через первый цвет меняется на зелёный | Второй материал, палитра и следующий потребитель тоже получают зелёный | Палитра и другие материалы сохраняют белый цвет | 6.9, 6.11 |
| Два обычных `Material` используют неявный `blendEquationNone`; через первый задаётся additive blending | Второй и новый материалы получают изменённые настройки | Их blending остаётся отключённым | 6.9, 6.11 |
| Два `Material.transparent` получают `blendEquationStandard`; через первый задаётся additive blending | Второй и новый материалы теряют стандартные коэффициенты смешивания | Их стандартное смешивание сохраняется | 6.9, 6.11 |
| Материалы используют `stencilFunctionAlways`; первый меняет `func` на `glNever` | Настройка второго и глобальный preset тоже становятся `glNever` | Другие потребители сохраняют `glAlways` | 6.9, 6.11 |
| Текстуры используют `texturePropertiesFramebuffer`; первый потребитель меняет фильтры с nearest на linear | CPU-настройки второго меняются сразу; GPU-фильтры меняются после его `install()`; новая текстура сразу получает linear | Фильтры остальных текстур и preset остаются nearest | 6.9, 6.11 |
| Два вызова `unitNode(program)`; через первый материал выключается запись глубины | У второго и следующего узла тоже выключается запись глубины | Настройки другого узла сохраняются | 6.4, 6.11 |

Минимальное воспроизведение изменения цвета, с восстановлением палитры:

```dart
final original = vm.Vector3.copy(colorWhite);
try {
  final first = Material('first')..setUniform(uColor, colorWhite);
  final second = Material('second')..setUniform(uColor, colorWhite);
  (first.getUniforms()[uColor]! as vm.Vector3).setValues(0, 1, 0);
  print(second.getUniforms()[uColor]); // (0, 1, 0), хотя второй не редактировался
} finally {
  colorWhite.setFrom(original);
}
```

Здесь и ниже сущности движка доступны из `package:chronosgl/chronosgl.dart`;
`vm` — импорт `package:vector_math/vector_math.dart`, `web` — `package:web/web.dart`.

Тесты цветов, blending и stencil проверяют значения, которые получают
потребители; чтение пикселей в эти воспроизведения не входит. Тест текстур
создаёт настоящий WebGL2-контекст и читает `TEXTURE_MIN_FILTER` и
`TEXTURE_MAG_FILTER`, в том числе **до** повторного `install()`:
изменение CPU-объекта само по себе ещё не меняет ранее установленное состояние GPU.
Тест `unitNode` создаёт настоящие программу и меши и проверяет общий материал.

Отдельные значения цвета, blend settings и texture properties служат контрольными
примерами: они сохраняются при изменении общего preset. Все изменённые глобальные
поля и map `emptyMaterial` восстанавливаются через `addTearDown`, в том числе при
неудачной проверке. WebGL-контексты освобождаются через `WEBGL_lose_context`.

В фазе 6 тесты следует перевести на создание отдельного варианта настройки
и проверку неизменности шаблона, второго и последующих потребителей. При переходе
к неизменяемым значениям изменить сами операции редактирования; ожидание общей
ссылки удалить. Для `unitNode` проверить независимую настройку материалов двух
узлов. Убрать пометки `Known bug`. Целевые правила зафиксированы в
[соглашениях о владении](1.4_OWNERSHIP_CONVENTIONS.md).

## Зависимость управления от числа кадров — фаза 4

[OrbitCamera.animate(elapsed)](../lib/src/webhelper/interactive_camera.dart)
не использует `elapsed`. Стрелки изменяют угол на `0.03` радиана **за вызов**,
`PageUp` умножает радиус на `0.99`, `PageDown` — на `1.01`.
Поэтому одинаковая продолжительность удержания клавиши при разных FPS даёт
разный результат. Даже `animate(0)` выполняет движение от удерживаемой клавиши.

Минимальный сценарий для одной камеры:

```dart
final camera = OrbitCamera(10, 0, 0, web.HTMLCanvasElement());
web.KeyboardEvent key(String type) => web.KeyboardEvent(
  type, web.KeyboardEventInit(which: Keyboard.left, keyCode: Keyboard.left),
);
double rotateFor200Ms(int fps) {
  camera.azimuth = 0;
  web.document.dispatchEvent(key('keydown'));
  try {
    for (var frame = 0; frame < fps ~/ 5; frame++) {
      camera.animate(1000 / fps);
    }
    return camera.azimuth;
  } finally {
    web.document.dispatchEvent(key('keyup'));
    camera.keyboard.afterFrameCleanup();
  }
}
print(rotateFor200Ms(30)); // около 0.18
print(rotateFor200Ms(60)); // около 0.36
```

Текущий `elapsed` передаётся в миллисекундах, как в примерах библиотеки.
Тесты синхронно моделируют одинаковую сумму временных шагов; реальный таймер,
RAF и частота работы машины на результат не влияют. `Keyboard` этой камеры
слушает `document`, даже когда мышь привязана к переданному canvas.

| Удержание клавиши | 30 FPS | 60 FPS | 120 FPS |
| --- | --- | --- | --- |
| Стрелка, 200 ms: модуль изменения угла | 0.18 rad | 0.36 rad | 0.72 rad |
| `PageUp`, 1 s: радиус при начальном 10 | 7.39700 | 5.47157 | 2.99380 |
| `PageDown`, 1 s: радиус при начальном 10 | 13.47849 | 18.16697 | 33.00387 |

Четыре теста стрелок проверяют оба направления по каждой оси. Продолжительность
200 ms удерживает polar ниже ограничения, чтобы насыщение угла не скрывало
зависимость от кадров. Два теста зума проверяют обе клавиши и значения
`10 * factor^frames`. Ещё один тест фиксирует поворот на `0.3` радиана
за десять вызовов с нулевым временем.

Положение наблюдателя восстанавливается из обратной матрицы вида. Это позволяет
проверять реальное движение, не опираясь на ошибочный `getPos()` из пункта 1.5.
После отпускания клавиши дополнительное обновление сохраняет позу. Каждый
сценарий сбрасывает радиус и углы, а `keyup` выполняется в `finally`.
На весь файл создаётся одна камера: отписки в текущем API нет, и подписки живут
до завершения браузерного окружения теста. Исправление подписок остаётся в 2.7 и 4.2.

В пунктах **4.3 и 4.10** заменить ожидания зависимости от кадров на одинаковые
позы при одинаковом времени, использовать `OrbitControls.update(deltaSeconds)`
с секундами и убрать `Known bug`. Сохранить проверки обеих осей, зума,
нулевого шага и прекращения движения после отпускания клавиши. Конкретные скорости
задать явно; ориентиры для сохранения поведения при 60 FPS описаны в
[соглашениях о единицах](1.3_UNITS_CONVENTIONS.md). События мыши и колеса
измеряют перемещение, поэтому умножать их дельты на время не следует.

## Запуск

Из корня проекта с установленными зависимостями и Chrome:

```sh
dart test -p golden_chrome test/shared_settings_reproduction_test.dart test/orbit_frame_rate_reproduction_test.dart
dart test -p golden_chrome -c dart2wasm test/shared_settings_reproduction_test.dart test/orbit_frame_rate_reproduction_test.dart
```

Полные проверки:

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Платформа `golden_chrome` со SwiftShader определена в
[dart_test.yaml](../dart_test.yaml). Все сценарии запускаются через публичный
импорт; браузер требуется для текущего API движка и событий ввода.

Все 13 воспроизведений прошли с JavaScript- и Wasm-компиляцией.
Статический анализ завершился без замечаний. Полные наборы прошли:
91 тест VM/JavaScript и 89 тестов VM/Wasm, включая сравнение изображений с эталонами.
Это подтверждает воспроизводимость отложенных ошибок; их исправления ещё впереди.
