# 2.1. Удаление WebGL-ресурсов через ChronosGL

Пункт **2.1** [плана рефакторинга](../REFACTORING_PLAN.md) выполнен.
В [ChronosGL](../lib/src/core/chronosgl.dart) добавлены недостающие операции
удаления для всех типов ресурсов, которые уже создаёт эта обёртка.

## Парные операции

| Создание | Удаление | Handle |
| --- | --- | --- |
| `createBuffer()` | `deleteBuffer(buffer)` — существующий метод | `GlBuffer` |
| `createVertexArray()` | `deleteVertexArray(vao)` | `GlVertexArrayObject` |
| `createFramebuffer()` | `deleteFramebuffer(framebuffer)` | `GlFramebuffer` |
| `createTexture()` | `deleteTexture(texture)` | `GlTexture` |
| `createTransformFeedback()` | `deleteTransformFeedback(transform)` | `GlTransformFeedback` |
| `createProgram()` | `deleteProgram(program)` | `GlProgram` |
| `createShader(kind)` | `deleteShader(shader)` | `GlShader` |
| `createSampler()` | `deleteSampler(sampler)` | `GlSampler` |

Все методы доступны через `package:chronosgl/chronosgl.dart`, возвращают `void`
и принимают ненулевой handle, как существующий `deleteBuffer()`.
Программу, возвращённую `compileWholeProgram()`, также можно передать
в `deleteProgram()`.

## Контракт

Методы непосредственно вызывают соответствующую операцию WebGL. Вызывающий код
отвечает за владение ресурсом, его принадлежность этому контексту и завершение
использования. Обёртка не вводит реестр handles, не перехватывает ошибки WebGL
и не очищает их: они доступны через `getError()`.

Повторное удаление того же ресурса сохраняет поведение WebGL. Удаление VAO,
framebuffer или transform feedback не удаляет буферы и текстуры, на которые
они ссылаются. Transform feedback должен быть неактивен при удалении.

Удаление прикреплённого шейдера и текущей программы может быть отложено:
`DELETE_STATUS` становится `true`, но ресурс остаётся доступен WebGL до
отсоединения от программ или прекращения использования соответственно.
Вызов `delete*` не является ожиданием завершения GPU-команд. Это следует
семантике [WebGL 1.0](https://registry.khronos.org/webgl/specs/latest/1.0/)
и [WebGL 2.0](https://registry.khronos.org/webgl/specs/latest/2.0/).

Эти низкоуровневые операции служат основой для `dispose()` владельцев ресурсов
в пунктах 2.2–2.3. Автоматическая очистка при компиляции, линковке и ошибках
создания остаётся в пункте 2.4; текущие пути создания здесь не менялись.
Правила владения описаны в [соглашениях 1.4](1.4_OWNERSHIP_CONVENTIONS.md).

## Проверки

[Браузерные тесты](../test/chronosgl_resource_deletion_test.dart) включены
в preset `all` и используют публичный импорт библиотеки. Состояние проверяется
через настоящий WebGL2-контекст: `isBuffer`, `isTexture` и остальные `is*`,
bindings, `DELETE_STATUS` и отсутствие ошибок.

11 тестов охватывают все восемь пар создания/удаления, обе стадии шейдеров,
повторное удаление, освобождение bindings, сохранность зависимых ресурсов
и отложенное удаление шейдера и программы.

```sh
dart analyze
dart test -p golden_chrome test/chronosgl_resource_deletion_test.dart
dart test -p golden_chrome -c dart2wasm test/chronosgl_resource_deletion_test.dart
```

Проверено на Dart 3.13.5: анализ без замечаний; все 11 тестов проходят
в JavaScript и все 11 — в Wasm.
