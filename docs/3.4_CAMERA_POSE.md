# 3.4. Хранение позы отдельно от вычисления матриц камеры

Пункт **3.4** [плана рефакторинга](../REFACTORING_PLAN.md) делает положение
и ориентацию единственным исходным состоянием новой `Camera`. Обе реализации,
`PerspectiveCamera` и `OrthographicCamera`, используют это состояние через
общий базовый класс. Публичный API пункта 3.2 сохранён.

## Состояние и вычисления

Внутренний универсальный `Transform` заменён двумя собственными компонентами:
мировым положением `Vector3` и нормализованной ориентацией `Quaternion`.
Камера не хранит матрицу как изменяемую позу и не извлекает положение или
ориентацию из матрицы вида. Масштаб, shear, отражение и родительская связь
по-прежнему не входят в контракт камеры.

| Операция | Что меняется или вычисляется |
| --- | --- |
| `setPosition`, `setPositionFromVector` | Только мировое положение; ориентация сохраняется точно |
| `setRotation` | Только нормализованная ориентация; положение сохраняется точно |
| `lookAt` | Ориентация по текущему положению, цели и up; положение сохраняется |
| `worldPosition`, `worldRotation` | Независимые копии исходных компонентов |
| `worldMatrix` | Новый снимок `C = T(position) * R(rotation)` с единичным масштабом |
| `viewMatrix` | Новый снимок `V = inverse(C)`; исходные компоненты не меняются |
| `viewProjectionMatrix` | Новый снимок `P * V`; поза не зависит от доступности проекции |

Изменения видны немедленно, без `update()`. Порядок чтения матриц не влияет
на последующие изменения позы. Изменение полученного снимка не меняет камеру,
а изменение камеры не меняет старые снимки.

`lookAt` выполняет однократное наведение: цель и up не сохраняются в камере.
Последующий перенос сохраняет ориентацию, а не наводит камеру повторно на
старую цель. Для слежения контроллер должен снова вызвать `lookAt`.

```dart
import 'package:chronosgl/camera.dart';
import 'package:vector_math/vector_math.dart' as vm;

final camera = PerspectiveCamera(near: 0.1, far: 1000)
  ..setPosition(3, 4, 12)
  ..lookAt(vm.Vector3.zero());
final previousView = camera.viewMatrix;

camera.setPosition(7, 8, 9); // Ориентация сохраняется.
final nextView = camera.viewMatrix;
// previousView остаётся снимком до переноса.
// nextView вычислен из новой позы; worldPosition равна (7, 8, 9).
```

## Проверка аргументов и ошибки вычисления

Конструкторы и setters копируют входные значения. Положение должно быть
конечным в Float32, кватернион — конечным и ненулевым. Наведение использует
прежние ограничения: несовпадающие глаз и цель, конечные компоненты,
ненулевой up и синус угла между направлениями больше `1e-6`.
Неверный аргумент даёт `ArgumentError` до записи соответствующего компонента.

Нормализация, проверка конечности и расчёт ориентации `lookAt` вынесены во
внутренний модуль `src/core/pose_math.dart`. `Transform` использует те же
операции, сохраняя свой матричный контракт, масштаб, поддержку shear и прежнее
поведение. Новый модуль не экспортируется через публичные библиотеки.

Конечная поза может дать непредставимую Float32-матрицу вида: например,
положение `(3e38, 3e38, 0)` с поворотом на `pi / 4` вокруг Z. Как и раньше,
чтение такой матрицы даёт `StateError`. Ошибка не изменяет компоненты,
мировую матрицу или проекцию. Позу можно читать и исправлять, даже если
предыдущую матрицу вида вычислить невозможно.

## Границы перехода

Результаты матриц и сигнатуры новых камер сохранены; миграция вызывающего
кода не требуется. `Spatial`, legacy-камеры, контроллеры и uniforms не меняются.
Воспроизведения ошибки legacy-позиции остаются до пункта 3.6, адаптер
`CameraUniforms` относится к 3.9. Пункт 3.4 не отмечает остальные задачи
фазы 3 или её итоговые критерии завершёнными.

## Проверки

[`camera_pose_test.dart`](../test/camera_pose_test.dart) добавляет 11 тестов
и включён в preset `all`. Для обеих проекций проверены:

- чередование изменений позы и чтения/порчи снимков матриц без обратного
  влияния на исходные компоненты;
- перенос после `lookAt` без сохранённой цели и с сохранением старых снимков;
- ошибка вычисления вида, сохранность позы и последующее восстановление;
- атомарность ошибочных изменений после чтения матриц;
- общие соглашения `lookAt` с `Transform`, включая независимость состояния
  и сохранение масштаба у `Transform`.

Отдельный подкласс с недоступной проекцией проверяет независимость операций
позы и вида от `projectionMatrix`. Существующие тесты камер, преобразований
и проекций продолжают проверять публичный контракт.

```sh
dart analyze
dart test test/transform_test.dart test/camera_test.dart test/camera_pose_test.dart test/projection_test.dart
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Результаты на Dart 3.14.0: `dart analyze` — без замечаний; отдельный
математический VM-набор — 65 тестов; полный VM/JavaScript-прогон — 416 тестов,
прогон с Wasm — 414 тестов (preset также выполняет VM-наборы; два legacy
DOM-теста предназначены только для JavaScript). Все 11 новых тестов проходят
на трёх платформах. Rendering goldens совпадают с существующими эталонами;
изображения не обновлялись.
