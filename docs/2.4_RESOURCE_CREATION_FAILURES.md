# 2.4. Очистка ресурсов при ошибках создания

Пункт **2.4** [плана рефакторинга](../REFACTORING_PLAN.md) выполнен.
Неудачное создание программы, текстуры или framebuffer освобождает уже
созданные собственные GPU-ресурсы. Переданные извне ресурсы сохраняются.

## Контракт ошибки

Каждый созданный handle учитывается до следующей операции инициализации.
При исключении библиотека пытается удалить все собственные ресурсы;
ошибка одного удаления не останавливает остальные. Вызывающий код получает
исходное исключение с исходным стеком. Вторичные ошибки очистки подавляются.
Для каждого handle выполняется не более одной попытки удаления.

Если сама операция удаления не дошла до WebGL, гарантируется попытка очистки,
а не физическое освобождение ресурса. Повторные попытки не выполняются —
это тот же принцип, что у `dispose()` из пункта 2.3.

## Компиляция и программа

[`ChronosGL.compileWholeProgram()`](../lib/src/core/chronosgl.dart)
учитывает оба временных шейдера сразу после создания. При ошибке создания,
компиляции, настройки transform feedback или линковки удаляются незавершённая
программа и все созданные шейдеры. Удаление программы снимает её ссылки
на шейдеры, поэтому их освобождение не остаётся отложенным из-за attachment.

При успехе оба шейдера отсоединяются и удаляются, а программа передаётся
вызывающему коду. Ошибка удаления временного шейдера тоже прерывает создание:
оставшиеся шейдеры и программа получают запросы удаления. Текущая рабочая
программа контекста не переключается.

[`RenderProgram`](../lib/src/core/render_program.dart) подготавливает набор
атрибутов до выделения GPU-программы. Если после линковки не удаётся получить
или сохранить uniform locations, созданная программа освобождается.
Оптимизированные компилятором uniforms с `null` location по-прежнему допустимы.
Существующий формат ошибок компиляции и линковки — строка с журналом WebGL —
сохранён; общий переход к типизированным ошибкам остаётся в пункте 7.7.

## Текстуры и framebuffer

[`TypedTexture`, `TypedTextureMutable`, `ImageTexture` и `CubeTexture`](../lib/src/core/textures.dart)
очищают свой handle при ошибке загрузки, выделения хранилища или установки
настроек. Это закрывает в том числе сбой конструктора вложенной текстуры,
когда framebuffer ещё не получил готовую обёртку. DOM-источники и переданные
настройки остаются у вызывающего кода.

[`Framebuffer.defaultFramebuffer()` и `.effect()`](../lib/src/core/framebuffer.dart)
создают и регистрируют собственные текстуры последовательно. Если вторая
текстура не создалась, первая освобождается. Если ошибка произошла позднее,
удаляются framebuffer и все собственные attachments. Обычный конструктор
`Framebuffer(cgl, ...)` удаляет только новый framebuffer, сохраняя внешние
текстуры, в том числе уже подключённые до сбоя. Именованные конструкторы
остаются generative: их можно вызывать из конструкторов наследников.

При ошибке восстанавливаются прежние привязки `READ_FRAMEBUFFER` и
`DRAW_FRAMEBUFFER` по отдельности. Конструкторы текстур восстанавливают
прежнюю привязку своего texture target; фабрика framebuffer восстанавливает
`TEXTURE_2D` на момент входа, включая сбой после создания первой текстуры.
При успешном создании сохраняется прежнее поведение: соответствующая
привязка сбрасывается в `null`. Полное сохранение состояния WebGL, включая
pixel-store settings, не вводится.

Ошибка WebGL при инициализации текстуры и неполный framebuffer теперь дают
`StateError` независимо от включения assertions. Отдельная stencil texture
при `depthStencilCombined = true` даёт `ArgumentError` до создания framebuffer.
Эти проверки нужны, чтобы не возвращать частично созданный объект в release.

## Проверки

[Браузерные тесты](../test/resource_creation_failure_test.dart) включены
в preset `all`. Используются настоящий WebGL2, счётчики создания/удаления,
проверки `isShader`, `isProgram`, `isTexture`, `isFramebuffer`, привязок,
`getError()` и пикселей после восстановления работы.

Проверяются реальные ошибки обоих shader stages, несовместимость varyings,
неизвестная transform feedback varying, неполный framebuffer, неправильный
формат attachment и нулевые размеры текстуры. Инъекции ошибок покрывают
создание handles, линковку, uniform locations, загрузку и настройки текстур,
подключение attachments, проверку полноты и сброс привязки. Ошибки удаления
проверяются вместе с сохранением исходного исключения и его стека.

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Проверено на Dart 3.13.5: анализ без замечаний; все 37 новых тестов проходят
в JavaScript и Wasm. Полные наборы проходят: 172 VM/JavaScript-теста и
170 VM/Wasm-тестов, включая эталонные изображения рендера. Два теста legacy
DOM предназначены только для JavaScript и не входят в запуск Wasm.
