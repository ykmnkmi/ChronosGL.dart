# 1.7. Сохранность пользовательского списка uniforms при отрисовке

Исправление выполнено в [обходе сцены](../lib/src/scene/render_phase.dart).
[Браузерные тесты](../test/scene_uniforms_test.dart) включены в preset `all`.
Правило владения описано в [соглашениях пункта 1.4](1.4_OWNERSHIP_CONVENTIONS.md).

## Причина ошибки

`Scene` сохраняет переданный список uniforms по ссылке. Ранее `RenderPhase.draw()`
добавлял в этот список служебную группу transforms, а `drawRecursively()` —
материал текущего узла. После успешной отрисовки элементы удалялись через
`removeLast()`, но во время вызова пользователь уже видел изменённый список.
Исключение прерывало очистку, оставляя служебные элементы для следующего кадра.
Список `const` или `List.unmodifiable` приводил к `UnsupportedError` при `add()`.

Прямой вызов `drawRecursively()` также изменял последнюю переданную группу,
записывая в неё матрицы узла через `updateTransforms()`.

Минимальный сценарий с созданными контекстом `cgl`, программой `program`
и узлом `node` с мешем и материалом:

```dart
final scene = Scene('scene', program, const <UniformGroup>[])..add(node);
final phase = RenderPhase('phase', cgl)
  ..viewPortW = 2
  ..viewPortH = 2
  ..add(scene);
phase.draw();
```

Имена доступны из `package:chronosgl/chronosgl.dart`. После исправления такой
список поддерживается; полный сценарий с чтением пикселей находится в тестах.

## Поведение после исправления

`RenderPhase.draw()` создаёт рабочий список из пользовательских групп и новой
служебной группы transforms. Для каждого рисуемого узла `drawRecursively()`
копирует map последней группы в отдельную группу, записывает туда матрицы узла
и формирует список для `RenderProgram.draw()` в прежнем порядке:
пользовательские группы, transforms, материал узла.

Последняя группа при прямом вызове `drawRecursively()` остаётся шаблоном
transforms. Её дополнительные uniforms сохраняются в рабочей копии.
Исходные список, группы и значения не изменяются обходом; копирование map
поверхностное, ресурсы и пользовательские значения не клонируются.

Материал и служебные группы больше не добавляются во входной список.
Поэтому исключение передаётся вызывающему коду без необходимости восстанавливать
его структуру. Следующий вызов собирает рабочие данные заново; материал родителя
не попадает в набор дочернего или соседнего узла.

`stats` остаётся выходным списком: записи успешно отрисованных узлов сохраняются
при последующей ошибке. Откат состояния WebGL и изменений, сделанных самим
пользовательским callback, в этот контракт не входит. `Scene` по-прежнему
хранит исходный список; изменение его состава между кадрами остаётся видимым.

## Регрессионные проверки

Семь тестов охватывают:

- Обычный и неизменяемый списки при успехе и исключении на втором узле.
  Состав проверяется внутри чтения uniforms и после выхода. После ошибки
  сохраняется одна запись статистики, а повторная отрисовка проходит.
- Пустой список `const` в `Scene`.
- Прямой рекурсивный обход с неизменяемым списком при успехе и исключении.
  Проверяются сохранность map последней группы, исходной матрицы и повторный вызов.

Сцена содержит контейнер с двумя узлами и разными материалами. Чтение всех
пикселей canvas 2 × 2 подтверждает итоговый зелёный цвет второго узла.
Дополнительно проверяются отсутствие ошибок WebGL и неинициализированных входов.

## Запуск

Из корня проекта с установленными зависимостями и Chrome:

```sh
dart test -p golden_chrome test/scene_uniforms_test.dart
dart test -p golden_chrome -c dart2wasm test/scene_uniforms_test.dart
```

Платформа `golden_chrome` использует SwiftShader и определена в
[dart_test.yaml](../dart_test.yaml). Полные проверки:

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Все семь новых тестов воспроизвели проблему на исходном коде с JavaScript-компиляцией
и прошли после исправления.
Статический анализ завершился без замечаний; полные наборы прошли:
67 тестов VM/JavaScript и 65 тестов VM/Wasm, включая сравнение изображений
с эталонами.
