Статус: подготовлено для ревью. Это целевой контракт для

Текущее поведение сверено с коммитом
`6a298e4ac64201c23ad454657772fefd5d1ada71`.

Оси, пространства и порядок преобразований заданы в
[пункте 1.2](1.2_COORDINATE_CONVENTIONS.md). Здесь фиксируются единицы чисел,

## 1. Общие правила

| Величина в целевом API | Единица и смысл |
| --- | --- |
| Угол поворота, азимут, elevation, roll | Радианы; положительное направление определяется пунктом 1.2 |
| `fovYRadians` | Полный вертикальный угол обзора в радианах |
| Угол конуса прожектора | Половина полного угла конуса в радианах; имя должно явно содержать `halfAngleRadians` |
| `deltaSeconds` | Прошедшее время одного обновления в секундах |
| `timeSeconds`, `durationSeconds` | Время от явно указанного начала и длительность в секундах |
| Положение, расстояние, геометрические размеры | Единицы соответствующего пространства сцены; автоматической привязки к метрам нет |
| Масштаб преобразования, aspect, коэффициент скорости воспроизведения | Безразмерные отношения |
| Размер элемента и обычное движение указателя | CSS-пиксели в браузерном адаптере |
| Viewport, framebuffer, экранный размер растеризованного примитива | Пиксели соответствующей цели рендеринга |
| Размер текстуры | Тексели конкретного mip-уровня |
| UV, NDC, нормализованная глубина | Безразмерные координаты; это разные пространства |
| Число сегментов, вершин, индексов, экземпляров | Целые количества, не длины и не байты |

Для смешивающихся величин использовать явные имена: `fovYRadians`,
`deltaSeconds`, `widthCssPixels`, `widthPixels`, `offsetBytes`, `vertexCount`.
Суффикс не обязателен у каждой координаты `x`, но единица и пространство должны
быть записаны в документации параметра. API не угадывает единицу по величине
числа: `90` не превращается автоматически в градусы, `1000` — в миллисекунды.

Все вещественные параметры должны быть конечными. Ошибки публичных аргументов
проверяются до изменения состояния и приводят к `ArgumentError`, включая
release-сборку; одного `assert` недостаточно. Конкретные ограничения приведены
ниже. Нулевой размер скрытого DOM-элемента обрабатывается отдельно от ошибочных
параметров математической проекции.

## 2. Углы и проекции

### Перспектива

`fovYRadians` — угол между верхней и нижней границами симметричного frustum.
`aspectRatio = viewportWidthPixels / viewportHeightPixels`.
Горизонтальный угол вычисляется из вертикального:

```text
radians = degrees * pi / 180
fovX = 2 * atan(tan(fovY / 2) * aspectRatio)
heightAtDistance(d) = 2 * d * tan(fovY / 2)
widthAtDistance(d) = heightAtDistance(d) * aspectRatio
```

Здесь `d > 0` — расстояние вдоль направления взгляда: соответствующая плоскость
имеет `zView = -d`. Это не расстояние до точки по диагонали.
При resize сохраняется вертикальный FOV, меняется горизонтальный.

Допустимы `0 < fovYRadians < pi`, `aspectRatio > 0`, `0 < near < far`.
`near` и `far` — расстояния в мировых единицах сцены при жёсткой позе камеры;
плоскости находятся на `zView = -near` и `zView = -far`.
Бесконечная дальняя плоскость и reversed-Z в этот контракт не входят.

Сейчас [`Perspective.update()`](../lib/src/core/projection.dart#L75)
переводит `_fov` из градусов в радианы перед вызовом `vector_math`.
В установленном `vector_math 2.4.3` `setPerspectiveMatrix()` использует
`tan(fovYRadians * 0.5)`: это именно **полный вертикальный** угол.
Комментарий «horizontal … divided by 2» у `_fov` неверен.
Существующий `updateFov(50)` соответствует новому
`fovYRadians: 50 * pi / 180`, примерно `0.872664626`.
Этот же угол сохраняется как значение по умолчанию при миграции.
Совместимая обёртка старого метода, если она будет оставлена, продолжает принимать
градусы; изменить единицу под прежним именем без миграции нельзя.

### Ортографическая проекция и свет

`left`, `right`, `bottom`, `top` — координаты границ в пространстве камеры,
а не ширина и высота. Полные размеры: `width = right - left`,
`height = top - bottom`. Требуются `left < right`, `bottom < top`, `near < far`.
Для ортографической проекции `near` может быть нулевым или отрицательным;
формулы `zView = -near/-far` сохраняются. Это необходимо, в частности,
для существующего объёма теней направленного света.

Проекция с явно заданными четырьмя границами не меняет их сама при resize.
Для режима подстройки под aspect выбирается явная политика. Базовый вариант
для новой камеры: сохранить центр и полную высоту, пересчитать ширину
`width = height * aspectRatio`. Чтобы сохранить старый вид
[`Orthographic`](../lib/src/core/projection.dart#L31), адаптер оставляет
`left`, `right`, `bottom` и вычисляет `top = bottom + width / aspectRatio`.
Это отдельная политика, её нельзя незаметно заменить сохранением высоты.

У [`SpotLight.angle`](../lib/src/core/illumination.dart#L137) уже радианы:
в данные света записывается `cos(angle)`. Это угол между осью и краем конуса,
поэтому целевое ограничение — `0 < halfAngleRadians < pi / 2`.
Полный угол конуса равен `2 * halfAngleRadians`.
Текущий FOV теневой камеры равен `2.1 * angle`: множитель включает запас,
а не другую единицу. Запас задаётся и документируется отдельно от угла света;
получившийся FOV должен также быть меньше `pi`.

`range` света — расстояние в мировых единицах, целевое значение строго больше
нуля. [`DirectionalLight.dim`](../lib/src/core/illumination.dart#L104)
задаёт **полуразмер** ортографического объёма: каждая пара границ равна
`[-dim, dim]`, полная ширина, высота и глубина — `2 * dim`; требуется `dim > 0`.
Угол поворота, половина угла конуса и полный FOV остаются разными параметрами,
хотя все измеряются в радианах.

## 3. Время и управление

### Часы, интервал и анимация

Математика и управление принимают секунды в `double`. `deltaSeconds >= 0` —
интервал, `timeSeconds` — позиция на временной шкале, а не интервал.
Для времени клипа и длительности допускается ноль, отрицательные значения
не допускаются. FPS измеряется в кадрах в секунду.
Типизированный `Duration`, например в `DrawStats`, сохраняет свой смысл;
при необходимости переводится через `inMicroseconds / 1000000.0`.

Браузерный callback `requestAnimationFrame` получает `DOMHighResTimeStamp`
в миллисекундах; преобразование выполняется один раз на входе приложения.
Это следует из [HTML: Animation frames](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#animation-frames)
и [High Resolution Time](https://www.w3.org/TR/hr-time-3/#sec-domhighrestimestamp).
Для временной шкалы приложения берётся первый настоящий callback за начало;
первый `deltaSeconds = 0`. Синтетический вызов `animate(0)` не устанавливает
начало часов. Нельзя вычитать из callback время `DateTime.now()`.

```text
deltaSeconds = (timestampMs - previousTimestampMs) / 1000
timeSeconds = (timestampMs - startTimestampMs) / 1000
fps = framesSinceSample / (sampleEndSeconds - sampleStartSeconds)
```

Пауза приложения и ограничение большого шага — явная политика вызывающего
цикла. После паузы можно сбросить предыдущую отметку, чтобы первый шаг был
нулевым; сами controls не отбрасывают время скрыто. Часы диагностики измеряют
реально прошедший интервал, даже если игровая шкала остановлена или замедлена.
Нулевой интервал выборки FPS не делится и не публикуется как новая оценка.

Целевой контракт `SkeletalAnimation`: длительность, времена всех ключей,
аргумент выборки позы и времена строк animation table выражены в секундах
от начала клипа. Индекс строки таблицы — отдельное целое число.
Импортёр преобразует **и ключи, и длительность** по одной формуле
`seconds = ticks / ticksPerSecond`. Частота должна быть конечной и положительной;
при отсутствующей или нулевой частоте необходим документированный источник
значения либо явный параметр импорта, а не неявное предположение `1` или `25`.
Для старого Three.js JSON входные `time` и `length` трактуются как секунды;
адаптер другого формата обязан указать свою единицу.

Выборка позы получает время в диапазоне `[0, durationSeconds]`; ключи упорядочены
и находятся в этом диапазоне. До первого ключа и после последнего удерживается
крайнее значение дорожки. Повторение выполняет проигрыватель явно:
`localTime = timeSeconds % durationSeconds` только при положительной длительности.
Клип нулевой длительности остаётся статическим, без `% 0`.
Сам переход на секунды не добавляет интерполяцию между ключами.

Сейчас [`importAnimationFromAssimpJson`](../lib/src/importer/assimp2json.dart#L147)
делит времена ключей на `tickspersecond`, но передаёт исходную `duration`.
[`Three.js importer`](../lib/src/importer/threejs.dart#L162) копирует обе величины
без преобразования. `BoneAnimation.setBoneMatrixAtTick()` сравнивает аргумент
с временами ключей без конвертации: слово `Tick` не описывает единую единицу.
Его [`_findTime()`](../lib/src/animation/skeleton_animation.dart#L184)
возвращает первый ключ при достижении последнего; это не корректная реализация
описанного удержания или циклического воспроизведения.
Эти изменения поведения выполняются отдельно при реализации, с проверками
начала, конца, нулевой длительности и импорта с частотой, отличной от `1`.

### Управление камерой

| Параметр/ввод | Единица | Применение за обновление |
| --- | --- | --- |
| Скорость поворота клавиатурой | радиан/секунду | `angle += angularSpeed * deltaSeconds` |
| Линейная скорость перемещения | единиц сцены/секунду | `position += velocity * deltaSeconds` |
| Скорость изменения логарифма радиуса | `1/секунду` | `radius *= exp(zoomRate * deltaSeconds)` |
| Накопленное движение мыши | CSS-пиксели | `angle += sensitivity * deltaPixels`, где sensitivity в радиан/CSS-пиксель |
| Нормализованное колесо | условные CSS-пиксели прокрутки | Знак и чувствительность определяются настройками; повторного умножения на время нет |

Дельты мыши и колеса уже описывают перемещение за события: их нужно суммировать
между обновлениями и потреблять один раз. Они не являются скоростью.
При `deltaSeconds == 0` непрерывное движение от клавиш отсутствует, но накопленные
события мыши могут быть обработаны. Без ввода нулевой шаг не меняет позу.

Сейчас [`OrbitCamera.animate()`](../lib/src/webhelper/interactive_camera.dart#L31)
игнорирует `elapsed`: клавиши добавляют `0.03` радиана и умножают радиус
на `0.99/1.01` за вызов. Для сохранения прежней скорости при условных 60 FPS
начальные ориентиры — `1.8` радиан/секунду и скорости зума
`60 * ln(0.99)` / `60 * ln(1.01)`. Это выбор настроек миграции, а не восстановление
несуществовавшей независимости от FPS. Прежние значения mouse sensitivity
не следует превращать в скорость в секунду.

В [пункте 1.9](1.9_SHARED_SETTINGS_AND_FRAME_RATE_REPRODUCTIONS.md) сохранены
воспроизведения для 30/60/120 FPS и нулевого шага. Переход к независимому
от кадров управлению и замена ожиданий тестов относятся к пунктам 4.3 и 4.10.

### Время и размеры в uniforms

[`uTime`](../lib/src/core/shader_object.dart#L277) уже описан как секунды
от начала программы. Целевой смысл — время выбранной приложением шкалы
в секундах от её старта; пауза и коэффициент воспроизведения задаются приложением.
Uniform не обновляется автоматически и не проверяет единицу пользовательского GLSL.
В примерах есть исключения: [animation](../example/animation/animation.dart#L178)
передаёт индекс строки, а [stencil2](../example/stencil2/stencil2.dart#L168) —
безразмерный коэффициент. При переносе они получают отдельные uniforms
для индекса и коэффициента. Замедление, например `timeMs / 2000`, записывается
как секунды с явным коэффициентом `0.5`, чтобы сохранить визуальную скорость.

[`StatsFps.updateFrameCount()`](../lib/src/misc/fps_meter.dart) сейчас ожидает
миллисекунды и делит число кадров на фиксированную секунду даже при более длинном
интервале. Новый интерфейс получает явно названное время в секундах и использует
фактический интервал. `DrawStats.duration` измеряет CPU-время участка отрисовки;
это не измерение времени исполнения GPU-команд.

## 4. Длины, геометрия и безразмерные параметры

Приложение выбирает масштаб сцены, например `1 единица = 1 метр`, и использует
его согласованно для координат, камер, света и импортируемых данных. Импортёр
не угадывает метры по величине координат. Преобразование единиц из метаданных
или настроек импорта должно одинаково учитывать геометрию, смещения узлов,
скелет и позиционные ключи. Локальный размер геометрии ещё не является размером
после преобразования узла; масштаб `Transform` — безразмерный множитель.

В новых сигнатурах `width/height/depth/length` означают полный размер;
`radius` — радиус; `halfWidth/halfHeight/halfDepth/halfExtent` — полуразмер.
Старые функции сохраняют смысл чисел до явной миграции сигнатуры.

| Текущий параметр | Фактический смысл | Правило миграции |
| --- | --- | --- |
| [`quadGeometry(size)`](../lib/src/shape/plane.dart#L7) | Координаты `±size`, сторона `2 * size` | Назвать `halfExtent` или передавать `width = height = 2 * size` |
| [`cubeGeometry({x, y, z})`](../lib/src/shape/cube.dart#L20), `wedgeGeometry` | Полуразмеры по трём осям | Явные half-параметры либо полные размеры `2*x`, `2*y`, `2*z` |
| [`gridGeometry(xstrips, ystrips, xlen, ylen)`](../lib/src/shape/plane.dart#L38) | Число ячеек и полные длины сторон | Сохранить полный размер; независимые размеры по осям и индексация исправлены в [1.8](1.8_GRID_GEOMETRY.md) |
| [`cylinderGeometry`](../lib/src/shape/cylinder.dart#L6) и варианты cone | Радиусы оснований и полная высота | Сохранить единицы; различать радиус и диаметр |
| [`icosahedronGeometry(scale)`](../lib/src/shape/icosahedron.dart#L78) | Радиус сферы, на которой лежат нормализованные вершины | Назвать `radius`, а не безразмерным масштабом трансформации |
| [`torusKnotGeometry(radius, tubeRadius)`](../lib/src/shape/torusknot.dart#L25) | Масштаб центральной кривой в единицах длины и радиус сечения | Первый `radius` не является наружным радиусом всего меша; `heightScale` безразмерен |
| [`Utils.makeStarMesh(..., dimension)`](../lib/src/misc/example_helper.dart) | Полная длина стороны области размещения | Сохранить полный размер при выносе в примеры |

Генераторы требуют положительных полных размеров, полуразмеров и радиусов;
для конуса разрешён нулевой радиус одного основания, но не обоих.
Радиус орбиты камеры также строго положителен.
Сегменты сетки — целые `>= 1`, сегменты
замкнутого кругового сечения — `>= 3`, число рекурсивных подразделений икосаэдра —
целое `>= 0`. Это разные способы задания детализации, их нельзя унифицировать
простым переименованием. Отражение выполняется преобразованием узла, а не
отрицательными размерами генератора.

UV обычно задаёт относительные координаты текстуры: диапазон `[0, 1]` описывает
один охват, значения вне диапазона допустимы при соответствующем wrapping.
`aspectRatio`, коэффициенты масштаба и нормализованные направления безразмерны.
Значение глубины после отображения NDC в `[0, 1]` не является расстоянием до
камеры; линейную глубину нельзя получать простым умножением на `far`.

## 5. Canvas, viewport и ввод

### Размер цели рендеринга

Размер DOM-элемента в CSS-пикселях и размер его drawing buffer хранятся отдельно.
Viewport задаётся целыми `x`, `y`, `width`, `height` в пикселях **текущего
framebuffer**; начало внизу слева, `x` растёт вправо, `y` вверх.
Aspect камеры берётся из размеров её viewport, не из окна браузера и не
обязательно из полного framebuffer.

В целевом `CanvasViewport` коэффициент `pixelRatio > 0` безразмерен, по умолчанию
равен `devicePixelRatio`; приложение может задать его явно.
Для положительного размера content box:

```text
requestedWidthPixels  = max(1, round(widthCssPixels  * pixelRatio))
requestedHeightPixels = max(1, round(heightCssPixels * pixelRatio))
```

Округление выполняется один раз на границе создания целочисленного buffer.
После установки размера используется фактический размер drawing buffer:
он может отличаться от запрошенного. WebGL не обновляет viewport автоматически
после resize и не подставляет DPR за приложение.
См. [WebGL: drawing buffer и viewport](https://registry.khronos.org/webgl/specs/latest/1.0/#2.2).

`CanvasViewport` обновляет viewport и aspect согласованно с фактическими размерами,
сохраняя заданный CSS-размер элемента. Изменение DPR обрабатывается даже без
изменения CSS-размера. Для отдельных framebuffer используются размеры их
attachments и явно заданный viewport; DPR не применяется к ним повторно.

Если CSS-ширина или высота нулевая, состояние считается временно неготовым:
отрисовка пропускается, последняя корректная проекция сохраняется, деления на ноль
и отрицательного размера нет. Когда размер снова положительный, размеры и
проекция обновляются перед отрисовкой. Пустой viewport высокоуровневого прохода
также означает пропуск draw. Отрицательные ширина/высота — ошибка аргумента.
Низкоуровневый `ChronosGL.viewport()` сохраняет правила WebGL, в том числе
возможность смещения за границы цели; автоматического clamp координат нет.

Сейчас оба [`*ResizeAware`](../lib/src/misc/example_helper.dart#L241)
копируют `clientWidth/clientHeight` прямо в `canvas.width/height`, не учитывая
DPR. `adjustAspect()` делит ширину на высоту без проверки нуля.
Существующие `RenderPhase.viewPort*`, `Framebuffer.activate()` и `ChronosGL.viewport()`
уже передают пиксели framebuffer, не CSS-пиксели.

### Указатель и колесо

Обычный указатель адаптер переводит в координаты content box canvas в CSS-пикселях,
с началом вверху слева. Дробная часть сохраняется. Для обычного drag движение
получается из разностей CSS-координат, независимо от DPR.
Сырые `movementX/Y` нельзя автоматически умножать на DPR: для pointer lock
нужен отдельный адаптер с документированной нормализацией и проверкой браузеров.
Спецификация определяет их через изменение `screenX/Y`, а не размер framebuffer.
См. [Pointer Lock: MouseEvent](https://www.w3.org/TR/pointerlock-2/#extensions-to-the-mouseevent-interface).

Колесо нормализуется с учётом `deltaMode`: пиксели, строки или страницы.
Единицу определяет [контракт WheelEvent](https://www.w3.org/TR/pointerevents4/#interface-wheelevent).
Для внутреннего значения в условных CSS-пикселях: pixel-дельта сохраняется,
line-дельта умножается на явно заданный `wheelLineHeightCssPixels`, page-дельта
по Y — на CSS-высоту области ввода. Универсального числа пикселей в строке нет;
коэффициент входит в настройки, а не скрывается в множителе чувствительности.
При нулевом размере области ввод управления не применяется.
Текущий [`Mouse`](../lib/src/webhelper/input.dart) приводит события к `int`,
перезаписывает дельты и игнорирует `deltaMode`; исправление относится к фазе 4.

Для content box без CSS-поворота/скоса и полного viewport точка `(xCss, yCss)`
переводится так, где `W/H` — фактические размеры buffer, `w/h` — размеры content box:

```text
xBuffer = xCss * W / w
yBuffer = (h - yCss) * H / h
xNdc = 2 * xBuffer / W - 1
yNdc = 2 * yBuffer / H - 1
```

Это непрерывные координаты границ. Для чтения одного пикселя и точки внутри
content box: `column = floor(xCss * W / w)`,
`row = H - 1 - floor(yCss * H / h)`. Вне области чтение не выполняется;
координаты не прижимаются скрыто к ближайшему пикселю.
Для частичного viewport сначала вычитаются его `x/y`, затем используются
его ширина/высота в формулах NDC. Border/padding и CSS-преобразования требуют
преобразования в content box до применения этих формул.

### Текстуры, шейдеры и память

Размеры texture/framebuffer и области `readPixels` — целые тексели/пиксели,
не размеры в единицах сцены. Создаваемая рабочая текстура имеет положительные
размеры в пределах возможностей контекста. Размеры mip-уровня относятся именно
к этому уровню. `gl_PointSize` и ширина растеризованной линии задаются в пикселях
цели; доступный диапазон ограничен реализацией WebGL.

Название uniform само по себе не определяет единицу. Сейчас
[`uCanvasSize` в Sobel](../lib/src/shader/sobel_shader.dart#L18) используется как
размер входной текстуры для шага соседнего текселя; в экранных эффектах размер
может относиться к viewport. Целевые параметры должны различать размер входной
текстуры и размер viewport, даже когда они случайно совпадают.

[`pointSpritesVertexShader`](../lib/src/shader/simple_shaders.dart#L39)
считает `gl_PointSize = uPointSize / gl_Position.z`: входной `uPointSize` не равен
экранному диаметру и зависит от проекции. В pixelate-шейдерах тот же uniform
означает полуразмер блока. При оформлении поддерживаемых shaders эти параметры
получают отдельные имена и единицы. Для размера точки в единицах сцены диаметр
в пикселях должен выводиться из проекции, глубины и высоты viewport; менять
формулу существующего шейдера незаметно при переименовании нельзя.

Низкоуровневые размеры памяти не переводятся по правилу размеров геометрии:

| Текущий API | Единица |
| --- | --- |
| `TypedData.length` / `lengthInBytes` | Число скалярных элементов / число байтов |
| `bufferDataSetSize`, `copyBufferSubData` | Размер и смещения в байтах |
| `vertexAttribPointer(size, stride, offset)` | Компоненты атрибута; stride и offset в байтах |
| `ChronosGL.draw(count, ..., offset, ...)` | `count` — индексы или вершины; при индексном draw offset в байтах, при drawArrays — номер первой вершины |
| `createAnimationTable` для RGBA float | `16 * boneCount * sampleCount` float-элементов; текстура `4 * boneCount` на `sampleCount` текселей |

В новых высокоуровневых сигнатурах неоднозначный `offset` разделяется по смыслу
на `offsetBytes` и `firstVertex`; низкоуровневые вызовы сохраняют единицы WebGL.

## 6. Миграция и проверяемые примеры

| Изменение | Где реализовать по плану | Что сохранить/проверить |

| `elapsed` → `deltaSeconds`; мышь и клавиши с разными размерностями | Фаза 4 | Одинаковое движение за одинаковое время; накопление нескольких событий |
| CSS / drawing buffer / viewport | Фаза 4 | DPR, частичный viewport, нулевой размер, восстановление и фактический размер цели |
| Названия размеров геометрии | Фазы 5 и 7 | Старые half-size значения не становятся полными без множителя `2`; grid исправляется в 1.8 |
| Секунды в импортёрах, клипах и debug-визуализаторе | Фазы 6–7 в рамках разделения модулей и уточнения контрактов | Длительность и ключи согласованы; отдельно покрыть поведение на концах дорожек |
| Время в FPS и смысл uniforms примеров | Фазы 6 и 8 | Фактический интервал FPS; индекс/коэффициент отдельно от времени; сохранить скорость эффектов |

Числовые ориентиры для будущих регрессионных проверок:

| Вход | Ожидаемый результат |
| --- | --- |
| `fovY = pi/2`, aspect `2`, `d = 10` | Высота `20`, ширина `40`, `fovX ≈ 2.214297436` радиана |
| Ортографические границы `[-4,4] × [-2,2]`, near `-3`, far `7` | Полные размеры `8 × 4`, плоскости `zView = 3` и `-7` |
| RAF: первый callback `10000 ms`, следующий `10016 ms` | Первый delta `0`; затем delta и время от старта `0.016 s` |
| Клип: duration `60 ticks`, ключ `30 ticks`, частота `30 ticks/s` | Длительность `2 s`, ключ `1 s` |
| Скорость `1.8 rad/s`, одна секунда при 30/60/120 обновлениях | Поворот `1.8 rad` с учётом погрешности сложения |
| 90 кадров за интервал `1.5 s` после начала измерения | `60 FPS`, не `90` |
| CSS `800 × 600`, pixelRatio `1.5`, фактический buffer равен запросу | Buffer `1200 × 900`, aspect `4/3` |
| Точка CSS `(200,150)` в предыдущем canvas | Непрерывная buffer-точка `(300,675)`, NDC `(-0.5,0.5)`, пиксель `(300,674)` |
| `quadGeometry(2)`; `cubeGeometry(x: 1, y: 2, z: 3)` | Полная сторона `4`; полные размеры `2 × 4 × 6` |
| 2 кости, 3 выборки в RGBA float animation table | 96 float-элементов, 384 байта, текстура `8 × 3` текселя |

При реализации дополнительно проверить NaN/Infinity, FOV `0` и `pi`, неверный
порядок near/far, допустимый отрицательный near у ортографической проекции,
нулевой aspect, нулевые размеры скрытого canvas, все три режима колеса,
дробные движения мыши и размер входной текстуры, отличный от viewport.
Это требования к будущим проверкам, а не утверждение, что текущая библиотека
их проходит. В пункте 1.3 код и тесты реализации не меняются.
