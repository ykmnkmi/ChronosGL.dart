# 3.10. Импорт математической части на Dart VM

Пункт **3.10** [плана рефакторинга](../REFACTORING_PLAN.md) закрепляет
доступность преобразований, камер и проекций без браузерных библиотек.
Граница уже реализована в 3.1–3.3 и сохранена при добавлении `CameraUniforms`
в 3.9; переносить математические реализации повторно не требуется.
Публичные экспорты и математическое поведение сохраняются.

## Публичные импорты

| Импорт | Экспортируемые типы | Назначение |
| --- | --- | --- |
| `package:chronosgl/core.dart` | `Transform` | Математическое преобразование local → parent |
| `package:chronosgl/camera.dart` | `Camera`, `PerspectiveCamera`, `OrthographicCamera`, `Projection`, `PerspectiveProjection`, `OrthographicProjection` | Мировая поза камеры, вид и проекции |
| `package:chronosgl/chronosgl.dart` | Общий API движка, включая рендер и `CameraUniforms` | Браузерная точка входа |

Первые два импорта можно использовать одновременно в CLI-программах,
VM-тестах и браузере. Для математического кода на VM нужно выбирать их
вместо общего `chronosgl.dart`. Внутренний `src/core/lib.dart` содержит
WebGL и uniforms и не является заменой публичному `core.dart`.

```dart
import 'package:chronosgl/core.dart';
import 'package:chronosgl/camera.dart';
import 'package:vector_math/vector_math.dart' as vm;

void main() {
  final model = Transform(position: vm.Vector3(1, 2, -3));
  final camera = PerspectiveCamera(near: 0.1, far: 100)
    ..setPosition(0, 0, 10);
  camera.lookAt(model.position);
  final localToClip = camera.viewProjectionMatrix..multiply(model.matrix);
  print(localToClip.transformed(vm.Vector4(0, 0, 0, 1)));
}
```

При сохранении примера в файле внутри пакета его можно запустить обычным
`dart run <file.dart>` без canvas, DOM или WebGL-контекста.

## Транзитивные зависимости

`core.dart` экспортирует самостоятельный `src/core/transform.dart`.
`camera.dart` экспортирует самостоятельные `src/camera/camera.dart` и
`src/camera/projection.dart`. Общие операции позы находятся в
`src/core/pose_math.dart`; они не импортируют библиотеку рендера.

Эта цепочка использует `vector_math/vector_math.dart` и математические
средства Dart SDK, включая typed data. В ней отсутствуют `package:web`,
`dart:html`, `dart:web_gl`, JavaScript interop, сцена и `UniformGroup`.
Направление зависимости адаптера остаётся односторонним:
браузерный рендер импортирует математическую камеру.

## Проверка границы

[`math_imports_test.dart`](../test/math_imports_test.dart) предназначен
только для VM и включён в preset `all`. Он находит пакет через разрешение
package URI, компилирует
[`support/math_imports.dart`](../test/support/math_imports.dart)
в kernel snapshot и запускает его отдельным процессом Dart.
Временный snapshot удаляется после теста, в том числе при ошибке.

Проверяемая программа использует только публичные `core.dart`, `camera.dart`
и `vector_math`, без `package:test` и браузерной среды. Она создаёт `Transform`,
обе проекции и оба типа камер через публичные контракты `Projection` и
`Camera`, наводит камеры на объект и вычисляет clip-координаты.
Компилятор VM проверяет всю выбранную цепочку импортов и экспортов:
транзитивный импорт браузерной библиотеки приводит к ошибке компиляции,
даже если её объявления не используются программой.

```sh
dart test -p vm test/math_imports_test.dart
```

Этот пункт проверяет доступность импортов. Итоговый набор математических
проверок положения, ориентации, обратимости и проекций относится к 3.11;
проверка значений uniforms в браузере — к 3.12. Остальные CPU-модули
и окончательные точки входа разделяются в последующих фазах плана.
