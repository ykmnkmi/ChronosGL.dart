# 2.6. Замена GPU-ресурсов

Пункт **2.6** [плана рефакторинга](../REFACTORING_PLAN.md): замена буферов
меша и attachments framebuffer согласована с владением из
[пункта 2.5](2.5_RESOURCE_OWNERSHIP.md).

## Общий контракт

1. Проверить аргументы и подготовить новый ресурс, сохраняя прежний.
2. Выполнить загрузку и подключение, проверить результат WebGL.
3. Зафиксировать новые ссылки, CPU-данные и явную передачу владения.
4. Освободить вытесненные собственные ресурсы, не используемые другими слотами
   этого же объекта. Заимствованные ресурсы только отключаются.

Ошибка подготовки сохраняет прежнюю рабочую конфигурацию и владение. Временные
собственные handles удаляются; переданный извне ресурс остаётся у вызывающего
кода. Очистка не подменяет исходное исключение и его стек.

Ошибка удаления старого ресурса возникает **после фиксации замены**: новая
конфигурация и её владение уже действуют. Для framebuffer продолжаются остальные
операции очистки, затем возвращается первая ошибка. Удаление каждого старого
handle запрашивается один раз, включая следующий `dispose()`; автоматического
повтора не предусмотрено, как и в [контракте освобождения](2.3_GPU_RESOURCE_DISPOSAL.md).

Повторная установка того же ресурса не удаляет его. Сохранение собственного
ресурса хотя бы в одном слоте сохраняет владение даже без `takeOwnership`.
Это локальный учёт слотов, а не глобальный подсчёт потребителей: перед заменой
владелец должен завершить работу внешних заимствующих потребителей. Возвращённый
ранее `getBuffer()` или attachment не продлевает жизнь ресурса.

## Буферы MeshData

| Операция | Поведение |
| --- | --- |
| `addVertices`, `addAttribute`, `addFaces` | Создать и загрузить новый собственный буфер; после успешного подключения заменить прежний |
| `changeAttributeBuffer` | Подключить готовый буфер; по умолчанию заимствовать, с `takeOwnership: true` принять владение |
| `changeVertexData`, `changeAttributeData`, `changeFaces` | Обновить содержимое существующего буфера, без замены handle и владельца |
| `clearData`, `dispose` | Освободить оставшиеся собственные ресурсы согласно пункту 2.2 |

При повторном `add*()` старые буферы больше не накапливаются до `dispose()`.
При ошибке загрузки/подключения сохраняются прежний handle, CPU-данные, число
вершин/индексов/экземпляров и тип индексов. Новый временный буфер освобождается
сразу. Проверки поддерживаемого атрибута, ширины и длины данных выполняются
до выделения буфера и не зависят от `assert`.

Неудачное подключение восстанавливает pointer, включение атрибута и divisor,
включая изначально пустой слот. Также восстанавливаются прежние VAO и
`ARRAY_BUFFER`; для индексов — прежний `ELEMENT_ARRAY_BUFFER` меша и активный VAO.
Сброс пустого слота использует разрешённую WebGL операцию `vertexAttribPointer`
с нулевым offset и отсутствующим буфером:
[спецификация WebGL](https://registry.khronos.org/webgl/specs/latest/1.0/).
При успехе сохраняется прежнее соглашение API: активен VAO изменяемого меша.

`changeAttributeBuffer()` меняет GPU-ссылку; сохранённый CPU-массив и размеры
меша не обновляются по содержимому внешнего буфера. Для обновления CPU-данных
вместе с заменой storage используются `add*()`. Изменение содержимого существующих
буферов через `change*Data()`/`changeFaces()` не обещает откат уже записанных байтов.
Прямое изменение VAO через низкоуровневый WebGL API обходит модель меша.

## Attachments Framebuffer

Добавлен `replaceAttachments(...)`, принимающий **полную новую конфигурацию**:
`colorTexture`, `depthTexture`, `stencilTexture`, `depthStencilCombined` и
`takeOwnership`. Неуказанные слоты становятся `null`; combined-режим по умолчанию
выключен. Неполная или недопустимая конфигурация отклоняется.

```dart
target.replaceAttachments(
  colorTexture: replacementColor,
  depthTexture: sharedDepth,
  takeOwnership: [replacementColor],
);
```

Переданный iterable владения копируется. Передавать можно только новые attachments;
текстура, уже принадлежащая этому framebuffer и оставленная в конфигурации,
может быть указана повторно. Чужой framebuffer-владелец запрещает передачу,
но не заимствование. Одна текстура в нескольких слотах освобождается один раз,
после удаления последнего слота.

Сначала создаётся временный framebuffer, который заимствует все предлагаемые
текстуры. Проверяются их состояние, WebGL-контекст, тип `TEXTURE_2D`, combined-режим,
полнота framebuffer и ошибки WebGL. Старый framebuffer при этом не изменяется.
При ошибке временный handle удаляется, прежние READ/DRAW bindings восстанавливаются,
а текстуры сохраняются. При успехе временный handle становится handle целевого
объекта, старый удаляется перед вытесненными собственными текстурами. READ/DRAW,
ссылавшиеся на прежний handle, переключаются на новый; посторонние bindings
сохраняются. Низкоуровневые сохранённые ссылки на старый framebuffer устаревают.

Синтаксис присваивания `colorTexture`, `depthTexture`, `stencilTexture` сохранён
через setters: он заменяет один слот, сохраняя остальные и combined-режим,
и выполняет те же проверки. Новая текстура заимствуется; для явного принятия
владения используется `replaceAttachments`. Присваивание теперь действительно
обновляет GPU attachment и может выбросить исключение. Для согласованной замены
нескольких слотов следует использовать один вызов `replaceAttachments`.

Экранный framebuffer не принимает attachments. Замена после `dispose()` даёт
`StateError` до выделения ресурсов. Автоматический resize этим пунктом не
добавляется: новые текстуры нужных размеров создаёт вызывающий код и передаёт
одной операцией; при неудаче он сохраняет ответственность за эти текстуры.

## Остальные ресурсы и границы

`Texture` и `RenderProgram` не имеют публичной замены собственного handle.
Для новой текстуры или программы создаётся отдельный объект, после успешного
создания переключаются потребители и освобождается старый объект его владельцем.
Обновление содержимого текстуры сохраняет её handle.

Материалы, uniforms, узлы и проходы заимствуют переданные зависимости. Замена
их ссылки сама по себе не удаляет меш, программу, framebuffer или текстуру.
Новый механизм не вводит рекурсивное освобождение сцены и не передаёт владение
ресурсом от одного существующего владельца другому.

## Проверки

[Браузерные тесты](../test/resource_replacement_test.dart) включены в preset `all`.
Проверяются немедленное освобождение, aliases, заимствование, повторная установка,
ошибки загрузки и подключения, восстановление CPU/GPU-состояния и bindings,
явное владение, combined depth/stencil, ошибки очистки после фиксации и запрет
замены для screen/disposed framebuffer. Используются настоящий WebGL2,
счётчики удалений и проверки пикселей после отката меша и замены attachment.

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Проверено на Dart 3.13.7: все 31 тест замены проходят в JavaScript и Wasm.
Полный запуск VM/JavaScript прошёл с 229 тестами; после добавления четырёх
дополнительных сценариев весь набор из 31 теста замены повторно прошёл в JavaScript.
Полный запуск VM/Wasm прошёл с 231 тестом, включая эталонные изображения рендера.
`dart analyze` — без замечаний, форматирование изменённых Dart-файлов проверено.
