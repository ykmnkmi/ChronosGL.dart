# 3.5. Матрица вида из обратного мирового преобразования

Пункт **3.5** [плана рефакторинга](../REFACTORING_PLAN.md) закрепляет вычисление
`Camera.viewMatrix` как обратной `Camera.worldMatrix`. Общая реализация уже
появилась в 3.2 и сохранена при выделении компонентов позы в 3.4. Проверка
не потребовала менять алгоритм: этот пункт уточняет документацию API и добавляет
отдельные регрессионные тесты для обеих проекций.

## Преобразования

Камера хранит мировое положение `eye` и нормализованную ориентацию. Её локальные
оси: вправо `+X`, вверх `+Y`, вперёд `-Z`. Масштаб, shear, отражение и
родительский узел не входят в текущий контракт.

```text
C = worldMatrix = T(eye) * R          camera-local → world
V = viewMatrix = inverse(C)          world → view
V = inverse(R) * T(-eye)

p_view = inverse(R) * (p_world - eye)
d_view = inverse(R) * d_world         направление, w = 0

V * (eye, 1) = (0, 0, 0, 1)
V * C ≈ I
C * V ≈ I
```

Для идеального жёсткого вращения `inverse(R) = transpose(R)`. Перенос матрицы
вида равен `-inverse(R) * eye`, а не просто `-eye`, если камера повёрнута.
Мировую позицию следует читать через `worldPosition`, а не через
`viewMatrix.getTranslation()`.

Порядок множителей существенен: сначала из мировой точки вычитается положение
камеры, затем применяется обратное вращение. Для направлений переноса нет.
Например, при `eye = (7, -3, 5)` и вращении `Ry(pi/2) * Rz(pi/2)` локальные
оси X, Y, Z переходят в мировые +Y, +Z, +X. Поэтому мировая точка `(1, 1, 7)`
имеет координаты `(4, 2, -6)` в пространстве вида, а перенос `V` равен
`(3, -5, -7)`.

## Реализация и границы

[`Camera.viewMatrix`](../lib/src/camera/camera.dart) берёт текущий снимок
`worldMatrix`, вызывает `Matrix4.inverted` и проверяет конечность результата.
Обратная матрица вычисляется из представленного мирового преобразования;
исходные положение и ориентация не перезаписываются. Результат — независимый
снимок, изменения позы видны при следующем чтении без `update()`.

`PerspectiveCamera` и `OrthographicCamera` наследуют один расчёт вида. Ни FOV,
ни aspect, ни clipping planes, ни ортографические границы в него не входят.
`viewProjectionMatrix` применяет проекцию после вида: `P * V`.

Матрицы и компоненты `vector_math` используют Float32. Равенства обратимости
проверяются с погрешностью; для больших координат применяется относительная
проверка. Если конечная поза даёт непредставимый перенос вида, чтение по-прежнему
выбрасывает `StateError`, не меняя позу. Этот случай и восстановление после него
покрыты тестами 3.4.

Публичные сигнатуры и результаты вычислений сохранены. `Spatial`, legacy-камеры
и uniforms не меняются: исправление legacy-позиции относится к 3.6, адаптер
`CameraUniforms` — к 3.9. Остальные пункты и итоговые критерии фазы 3 этим
изменением не закрываются.

## Проверки

[`camera_view_matrix_test.dart`](../test/camera_view_matrix_test.dart) содержит
9 тестов и включён в preset `all`. Проверяются:

- единичная ориентация и перенос, переход глаза в начало координат,
  отсутствие переноса у направлений;
- составной yaw и локальный roll с заранее вычисленными точками и осями,
  включая правильный перенос обратной матрицы;
- 64 воспроизводимые позы для каждой камеры: независимый эталон обратного
  вращения по формуле Родрига, оба произведения `V * C` и `C * V`, возврат
  точек после преобразования туда и обратно;
- большие конечные координаты порядка `1e30`, конечность вида и сохранение
  направления осей;
- неизменность вида при изменении параметров обеих проекций и соответствие
  `P * V` последовательному преобразованию world → view → clip.

```sh
dart analyze
dart test test/transform_test.dart test/camera_test.dart test/camera_pose_test.dart test/camera_view_matrix_test.dart test/projection_test.dart
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Результаты на Dart 3.14.0: `dart analyze` — без замечаний; отдельный
математический VM-набор — 74 теста; полный VM/JavaScript-прогон — 434 теста,
прогон с Wasm — 432 теста (preset также выполняет VM-наборы; два legacy
DOM-теста предназначены только для JavaScript). Все 9 новых тестов проходят
на трёх платформах. Rendering goldens совпадают с существующими эталонами;
изображения не обновлялись.
