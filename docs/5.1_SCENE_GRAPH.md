# 5.1–5.6. Узлы, группы отрисовки и проходы

Общий `Node` хранит локальное преобразование `Spatial.transform`, флаг
`enabled` и упорядоченный список дочерних связей. `GroupNode` — контейнер:
свойств меша и материала у него нет. `MeshNode` требует ненулевые `mesh`
и `material`; рисуется сам, затем обходит детей. Эти ресурсы заимствованы:
удаление связи или замена ссылки не вызывает `dispose()`.

```dart
final root = GroupNode('root');
root.add(MeshNode('cube', mesh, material));
final batch = RenderBatch('objects', program, [CameraUniforms(camera)])
  ..add(root);
final pass = RenderPass('main', cgl)
  ..viewPortW = canvas.width
  ..viewPortH = canvas.height
  ..add(batch);
pass.draw();
```

`Node(...)` и `Node.container(...)` сохранены как устаревшие фабрики конкретных
типов. Статический тип результата остаётся `Node`; для доступа к ресурсам
нужен `MeshNode` или проверка типа. `MeshNode.meshData` — устаревший alias
`mesh`. `Scene` и `RenderPhase` — aliases `RenderBatch` и `RenderPass`.
Пользовательские подклассы следует наследовать от `GroupNode` или `MeshNode`:
публичного generative-конструктора у общего `Node` больше нет.

## 5.3. Преобразование относится к пути обхода

Для каждого посещения вычисляется `world = parentWorld * local`. Корень
получает единичного родителя; обход идёт в глубину, сначала родитель, затем
дети в порядке добавления. Один узел может входить в несколько ветвей DAG:
он рисуется для каждого пути, с отдельной мировой матрицей. Постоянного
единственного родителя и единственной мировой позы у общего узла нет.

Матрицы `uTransformationMatrix`, `uModelMatrix` и `uNormalMatrix` каждого draw
независимы от следующих посещений. Локальная матрица копируется, мировая
вычисляется для пути, normal matrix — обратная транспонированная матрица
верхнего блока мировой матрицы. Переданный `parent` не меняется.
`updateModelMatrix` возвращает независимое значение; сохранённый внутри узла
снимок нужен только для прежнего явного вызова `updateTransforms` без матрицы.

Цикл в текущем пути вызывает `StateError`. Набор посещений не глобальный:
общие узлы DAG допустимы. После исключения временный путь очищается; после
исправления связей следующий кадр может рисоваться обычным образом.
Изменять структуру графа следует между вызовами отрисовки.

## 5.4–5.5. Batch и pass

`RenderBatch` связывает одну программу, свои корни и группы uniforms.
Список uniforms копируется при создании; группы, программа, узлы и ресурсы
узлов остаются заимствованными. Изменять состав следует через `batch.uniforms`.
Отключённые batch, программа или узел пропускаются; отключённый узел пропускает
и своё поддерево.

`RenderPass` хранит порядок batch, framebuffer и viewport. `add`, `remove`
и `removeAll` меняют только связи; `batches` возвращает неизменяемый снимок.
Порядок проходов определяется порядком вызовов `draw()` вызывающим кодом.

Каждый включённый проход с ненулевым viewport активирует framebuffer один раз
перед всеми batch и применяет выбранную маску очистки. По умолчанию выбраны
color, depth и stencil. Setter-ы `clearColorBuffer`, `clearDepthBuffer` и
`clearStencilBuffer` управляют битами независимо. Для наложения проходов
нужные очистки отключаются явно. Пустой viewport или выключенный pass
не активирует и не очищает framebuffer; отрицательный размер включённого
прохода вызывает `ArgumentError`.

## 5.6. Владение коллекциями и ошибки

Draw создаёт собственный список uniforms и группу преобразований, сохраняя
исходные списки, группы, значения матриц и ресурсы. Поддерживаются const
и неизменяемые входные списки. Ошибка uniform или draw не оставляет временные
группы в пользовательских коллекциях и не портит обход следующего кадра.
Успешно добавленные записи в выходной `stats` при последующей ошибке остаются;
полного отката framebuffer или глобального состояния WebGL нет.
