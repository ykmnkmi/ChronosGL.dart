# 3.1. Компонент Transform и переход от Spatial

Пункт **3.1** [плана рефакторинга](../REFACTORING_PLAN.md) вводит
[`Transform`](../lib/src/core/transform.dart) — самостоятельное математическое
состояние объекта. Компонент доступен через `package:chronosgl/core.dart`
на VM и в браузере, а также через существующий `chronosgl.dart`.
Новая точка входа `core.dart` пока экспортирует только `Transform`;
остальные сущности из карты API будут переноситься в своих пунктах плана.

## Смысл состояния

Матрица всегда переводит локальные координаты в пространство родителя:
`pParent = L * pLocal`. Векторы — столбцы, данные `vector_math` хранятся
по столбцам. Компонентное представление использует `L = T * R * S`:
сначала масштаб, затем вращение, затем перенос. Система координат правая;
локальное направление вперёд — `−Z`, вверх — `+Y`.

`position` задана в пространстве родителя, `rotation` — нормализованный
кватернион, `scale` — знаковый локальный масштаб. Нулевые и отрицательные
масштабы допустимы. Направления `right`, `up`, `back`, `forward` определяются
вращением, поэтому масштаб и отражение не меняют длину или знак шага движения.

Компонент не хранит родителя или последний результат обхода сцены.
Для конкретного пути графа вызывающий код вычисляет `W = WParent * L`.
У общего узла в DAG могут быть разные мировые матрицы при одном `Transform`.
Матрицы вида и проекции не являются состоянием этого компонента.

## Изменения и владение

| Операция | Смысл |
| --- | --- |
| `setPosition(x, y, z)`, `setPositionFromVector(v)` | Установить положение относительно родителя, сохранить линейную часть |
| `translate(x, y, z)` | Прибавить смещение в осях родителя |
| `translateLocal(x, y, z)` | Повернуть смещение собственным `R`, затем прибавить к положению; масштаб не влияет |
| `setRotation(q)` | Нормализовать и установить ориентацию, сохранить положение и масштаб |
| `rotateLocal(axis, angleRadians)` | `Rnew = R * Rdelta` |
| `rotateParent(axis, angleRadians)` | `Rnew = Rdelta * R`; положение не вращается вокруг начала координат |
| `setScale(x, y, z)` | Установить знаковый масштаб, сохранить положение и ориентацию |
| `lookAt(target, upHint: ...)` | Направить собственную ось `−Z` к цели в пространстве родителя, сохранить положение и масштаб |
| `setTRS(position: ..., rotation: ..., scale: ...)` | Явно заменить всё состояние компонентами |
| `setMatrix(matrix)` | Скопировать аффинную матрицу без изменения её элементов |

Все изменения видны немедленно, отдельный `update()` не нужен.
Входные векторы, кватернионы и матрицы копируются. Getters возвращают
независимые снимки: изменение `transform.matrix` или `transform.position`
не меняет компонент. `copyMatrixInto(out)` заполняет переданное хранилище;
оно остаётся собственностью вызывающего кода. GPU-ресурсов и `dispose()` нет.

Аргументы должны быть конечными и представимыми в Float32 (`vector_math`).
Нулевой кватернион или ось вращения недопустимы. `lookAt` отклоняет совпадение
цели с положением, нулевой `upHint` и почти параллельные направления:
синус угла между ними должен быть больше `1e-6`. По умолчанию `upHint = +Y`.
Плохие аргументы дают `ArgumentError` до изменения состояния, без зависимости
от `assert`. Автоматической подмены направления вверх нет.

## Импорт матриц, shear и вырожденные случаи

`Transform.fromMatrix` и `setMatrix` принимают конечную аффинную матрицу
с точной нижней строкой `(0, 0, 0, 1)`. Проективная матрица отклоняется.
Проверка формы матрицы не определяет её назначение: вызывающий код обязан
передавать local → parent, а не аффинную матрицу вида старого `Spatial`.

Матрица сохраняется точно, включая shear, отражение и нулевой масштаб.
Для невырожденного TRS дополнительно восстанавливаются компоненты.
Ортогональность нормализованных столбцов проверяется с допуском `1e-5`;
погрешность обратной сборки ограничена `1e-5` длины каждого линейного столбца.
Большая позиция или масштаб по другой оси не маскируют shear.
При отражении отрицательный масштаб назначается оси X: исходные знаки
отдельных осей невозможно однозначно восстановить только из матрицы.

`hasTRS == false` означает, что матрица содержит shear, вырождена либо
не допускает восстановление компонентов в этих числовых пределах.
В таком состоянии доступны чтение/запись матрицы, позиция и `translate`.
Чтение ориентации, масштаба, направлений и компонентные изменения, включая
`lookAt` и `translateLocal`, дают `StateError`. Это сохраняет данные вместо
неявного удаления shear. Для явной замены используется `setTRS`.

У компонента, созданного через TRS, ориентация известна даже при нулевом
масштабе, поэтому такие изменения разрешены. При импорте вырожденной матрицы
утраченная ориентация не угадывается. Обращение матрицы не входит в API 3.1;
проверки обратимости камеры будут реализованы вместе с её контрактом.

## Переход от Spatial

`Spatial`, `Node`, `OrbitCamera`, `Perspective` и `Orthographic` сохраняют
прежнее поведение. `Spatial` не становится alias или подклассом `Transform`:
его матрица после `lookAt()` является view-матрицей, а до этого часто
используется как объектное преобразование. Неявная замена изменила бы рендер.

| Старое использование | Переход |
| --- | --- |
| `Spatial` для положения объекта | Отдельный компонент `Transform`; имя и связи хранятся владельцем |
| `setPos`, `setPosFromVec`, `getPos` | `setPosition`, `setPositionFromVector`, снимок `position` |
| `translate`, `addPos` | `translate` в пространстве родителя; множитель включить в смещение явно |
| `rotX/Y/Z` | `rotateLocal` с соответствующей единичной осью и углом в радианах |
| `moveForward/Right/Up` | `translateLocal(0, 0, -distance)`, `(distance, 0, 0)`, `(0, distance, 0)`; старое чтение строк матрицы не переносится |
| `getRight/Up/Back` | Снимки `right/up/back`, определённые вращением и столбцами базиса |
| Прямая правка `transform` | Компонентные методы либо правка снимка с последующим `setMatrix` |
| `lookUp/Down/Left/Right`, `rollLeft/Right` | Явно выбрать ось, знак угла и пространство вращения |
| `setPosFromSpherical` | Рассчитать координаты по соглашению 1.2, передать в `setPosition`; управление орбитой относится к фазе 4 |
| `Spatial` как камера, `getViewMatrix`, `getEyePosition` | Оставить legacy-путь до введения `Camera` и `CameraUniforms` в следующих пунктах фазы 3 |

Переходный мост для существующего узла — явная копия перед обходом/отрисовкой:

```dart
import 'package:chronosgl/chronosgl.dart';
import 'package:vector_math/vector_math.dart' as vm;

final pose = Transform()..setPosition(0, 0, 10);
pose.lookAt(vm.Vector3.zero());
final node = Node.container('object');
pose.copyMatrixInto(node.transform);
```

Это независимые состояния: после изменения `pose` копирование нужно повторить.
В обратную сторону `Transform.fromMatrix(node.transform)` подходит только
при известном объектном смысле матрицы. Для старой камеры после `lookAt`
такое копирование не является миграцией позы. Автоматическое переподключение
сцены, новые камеры и исправление `uEyePosition` остаются в следующих пунктах.
Воспроизведения старой ошибки камеры из 1.5 продолжают проходить.

## Проверки

[`transform_test.dart`](../test/transform_test.dart) выполняется на VM и в
браузере. Проверены порядок TRS и вращений, локальные/родительские смещения,
снимки, сохранение положения при наведении, ошибки без частичного изменения,
отражения, нулевой масштаб, shear и разные родительские пути.
[`transform_compatibility_test.dart`](../test/transform_compatibility_test.dart)
проверяет публичные экспорты и копирование в существующий `Node`.
Оба набора включены в preset `all`.

```sh
dart analyze
dart test test/transform_test.dart
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Результаты: `dart analyze` — без замечаний; отдельный VM-набор — 17 тестов;
полный VM/JavaScript-прогон — 315 тестов; прогон с Wasm — 313 тестов
(VM-наборы также выполняются, два legacy DOM-теста предназначены только для JS).
Новые 17 математических проверок проходят на всех трёх платформах,
два теста совместимости — в JavaScript и Wasm. Rendering goldens совпадают
с существующими эталонами; изображения не обновлялись.

Пункт 3.1 не завершает всю фазу 3: общий контракт камер, проекции, uniforms
и миграция их потребителей ещё предстоят.
