## 1. Оси и направление взгляда

Локальные пространства объектов, мировое пространство и пространство камеры
используют **правую систему координат**: `X × Y = Z`.
Мировая ось `+Y` считается направлением вверх по умолчанию.

| Ось | Объект/камера с единичной ориентацией |
| --- | --- |
| `+X` | Вправо (`right`) |
| `+Y` | Вверх (`up`) |
| `+Z` | Назад (`back`) |
| `−Z` | Вперёд (`forward`), направление взгляда камеры |

Для камеры в начале координат с единичной ориентацией видимые точки перед ней
имеют отрицательный `z` в пространстве камеры. `+Z` не означает «к наблюдателю»
для произвольно повёрнутой камеры: направления определяются её ориентацией.
Для `lookAt()` направление вперёд объекта также считается локальным `−Z`.
Импортированная модель, у которой геометрическое «лицо» направлено иначе,
требует явного корректирующего преобразования.

Положительное вращение следует правилу правой руки. Например, вращение вокруг
`+Z` на четверть оборота переводит `(1, 0, 0)` в `(0, 1, 0)`.
Выбор произвольного `upHint` при наведении меняет ориентацию конкретного объекта,
но не мировое соглашение об осях.

## 2. Векторы и хранение матриц

Вычисления используют **векторы-столбцы** и умножение `M * v`.
Точка представляется как `(x, y, z, 1)`, направление — как `(x, y, z, 0)`.
Перенос действует на точки, но не на направления. Это правило относится
к аффинным преобразованиям; нормали имеют отдельное правило ниже.

Матрицы `Matrix4` и данные для GLSL хранятся по столбцам:

```text
storage[4 * column + row] = M[row, column]

M = [ m00  m01  m02  tx ]
    [ m10  m11  m12  ty ]
    [ m20  m21  m22  tz ]
    [  0    0    0    1 ]

translation = storage[12], storage[13], storage[14]
```

У матрицы положения и ориентации первые три столбца задают образы локальных
осей `+X`, `+Y`, `+Z` в пространстве назначения. Для ортонормального базиса:

| Направление | Элементы `Matrix4.storage` |
| --- | --- |
| `right` | `0, 1, 2` |
| `up` | `4, 5, 6` |
| `back` | `8, 9, 10` |
| `forward` | Отрицание `back` |

Для матрицы с масштабом или сдвигом формы эти столбцы не обязаны быть единичными
и взаимно перпендикулярными. Направления управления объектом определяются
его вращением, а не ненормированными столбцами произвольной матрицы.

Передача матриц в uniforms выполняется без транспонирования (`transpose: false`),
как уже сделано в [RenderProgram](../lib/src/core/render_program.dart#L191).
Порядок хранения и порядок применения преобразований — разные соглашения:
по столбцам хранится и `A * B`, и `B * A`, но результаты обычно различаются.

## 3. Локальное и мировое преобразование

`L` — локальная матрица узла, переводящая его координаты в пространство родителя.
`W` — матрица, переводящая координаты узла в мировое пространство для конкретного
пути обхода. Для корневого узла родительская матрица равна единичной.

```text
W_root  = L_root
W_child = W_parent * L_child

p_parent = L_child * p_local
p_world  = W_child * p_local
```

Таким образом, правый множитель применяется первым. Это сохраняет существующий
порядок [Node.updateModelMatrix()](../lib/src/scene/node.dart#L47).
Положение в локальном `Transform` задаётся относительно родителя; оно не является
мировой позицией при неединичном преобразовании родителя.

При построении матрицы из переноса, вращения и масштаба используется:

```text
L = T * R * S
```

Сначала применяется масштаб в локальных осях, затем вращение, затем перенос.
`R` — собственное ортонормальное вращение; при представлении кватернионом он
нормализован. `Transform` не хранит матрицу проекции или матрицу вида камеры
под видом локального преобразования.

Аффинная матрица, полученная из импорта или произведения матриц, может содержать
сдвиг формы (shear). Нельзя без проверки разложить её в TRS и потерять часть
преобразования. Даже произведение двух TRS с неравномерным масштабом может иметь
такой эффект. Редактирование ориентации и масштаба, включая `lookAt()`, требует
представления, в котором эти компоненты определены. Если входная аффинная матрица
не допускает принятого TRS-представления без потерь, такие операции отклоняются
с `StateError`; явные операции над матрицей остаются доступны.
Операции, требующие обратной матрицы, должны отклонять вырожденный
случай с понятной ошибкой; подстановка единичной матрицы или передача NaN не является
допустимым результатом. Наличие нулевого масштаба само по себе не запрещает
операции, которым обращение матрицы не требуется.

### Пространство операций

| Операция | Целевой смысл |
| --- | --- |
| Установка локального положения | Координаты в пространстве родителя |
| Перенос в пространстве родителя | Прибавление к локальному положению без поворота вектора смещения |
| Перенос в собственных осях | Поворот вектора смещения собственным `R`; собственный масштаб не увеличивает шаг |
| Локальное вращение | Обновление ориентации `R_new = R * R_delta` |
| Вращение относительно осей родителя | Обновление ориентации `R_new = R_delta * R` |
| Установка мировой позиции дочернего узла | Перевод мировой точки через `inverse(W_parent)` перед записью локальной позиции |

Операции изменения ориентации сохраняют положение и масштаб. Умножение всей
матрицы на вращение слева, которое также вращает положение вокруг начала
координат, является другой операцией и не должно скрываться под изменением
ориентации. Для мировых операций требуется явный контекст родителя/пути.

При миграции существующего `translate()` сохраняется смысл смещения
в пространстве родителя; для собственного пространства вводится явно
обозначенная операция. Существующие `rotX/rotY/rotZ` соответствуют локальному
изменению ориентации. Конкретные имена дополнительных методов и совместимость
остальных помощников вращения уточняются в фазе 3.

### Общие узлы и DAG

Один узел может встречаться в нескольких ветвях графа. В этом случае у него
есть одна локальная матрица и несколько мировых матриц, по одной на путь.
Контекст отрисовки, вычисления нормалей и мировых операций должен указывать путь
или предоставлять соответствующую `W_parent`.

Кэш последнего обхода нельзя выдавать за единственную мировую позицию узла.
Получение мировой матрицы без контекста допустимо только при однозначном пути.
Циклы в графе запрещены; повторное использование узла в разных ветвях циклом
не является. Эти правила реализуются при переработке сцены в фазе 5.

## 4. Положение камеры и матрица вида

`C` — мировое преобразование камеры: camera-local → world.
`V` — обратное преобразование: world → view.

```text
C = [ R  eye ]
    [ 0   1  ]

V = inverse(C)
p_view = V * p_world
eye_world = C * (0, 0, 0, 1)
V * eye_world = (0, 0, 0, 1)
```

Мировая поза камеры является жёстким преобразованием: перенос и вращение
с `det(R) = +1`. Масштаб, отражение и shear не входят в позу камеры.
Если камера привязывается к узлу, адаптер должен получить однозначный мировой
контекст и проверить это ограничение. Неподходящая матрица отклоняется;
масштаб не удаляется молча. Явное извлечение позы из более общего преобразования
может быть отдельной операцией, но не неявным поведением `Camera`.

Камера хранит собственную мировую позу независимо от прохода рендера.
Матрица вида вычисляется из неё и не перезаписывает положение или ориентацию.
`PerspectiveCamera` и `OrthographicCamera` используют одинаковое соглашение о позе
и отличаются проекцией.

### `lookAt()`

У `Camera.lookAt(target, upHint)` цель и опорное направление вверх заданы
в мировом пространстве. У `Transform.lookAt(target, upHint)` они заданы
в пространстве родителя. Это различие должно быть видно в документации методов.
Для наведения узла на мировую цель сначала требуется его контекст родителя.

При `eye` и `target` в одном пространстве:

```text
forward = normalize(target - eye)
right   = normalize(cross(forward, upHint))
up      = cross(right, forward)
back    = -forward

R = columns(right, up, back)
```

Полученный базис задаёт ориентацию. Наведение сохраняет `eye`, а для объекта —
также существующий масштаб. `upHint` задаёт желаемую сторону вверх; итоговый `up`
ортогонален направлению взгляда и может отличаться от `upHint`.

Нулевая разность `target - eye`, нулевой `upHint`, параллельные направления
и нечисловые/бесконечные компоненты являются недопустимыми входами.
Метод выдаёт `ArgumentError` и сохраняет предыдущее состояние. Автоматический
выбор другой оси не входит в базовый контракт `lookAt()`; контроллер может
предотвратить вырождение ограничением углов или явным выбором `upHint`.
Числовые допуски задаются при реализации и проверяются тестами.

## 5. Проекция и uniforms

`P` переводит координаты камеры в однородные clip-координаты.
`M` — мировая матрица текущего экземпляра меша, то есть `W` его пути в графе.

```text
p_world = M * vec4(position_local, 1)
p_view  = V * p_world
p_clip  = P * p_view
p_ndc   = p_clip.xyz / p_clip.w

gl_Position = P * V * M * vec4(position_local, 1)
```

Последнее выражение сохраняет порядок существующего
[стандартного vertex shader](../lib/src/shader/fragment.dart#L3).
Деление на `w` происходит после вычисления `gl_Position`.
Для используемых проекций NDC имеет `x` и `y` от `−1` до `+1` в пределах кадра;
ближняя плоскость соответствует `z_ndc = −1`, дальняя — `+1`.
Плоскости `z_view = -near` и `z_view = -far` следуют тому же правилу для
перспективной и ортографической матриц. NDC не является пространством позы
объекта: соглашения о базисе камеры нельзя применять к результату проекции.

| Uniform | Пространство и содержимое |
| --- | --- |
| `uTransformationMatrix` | Локальная матрица `L`, local → parent; историческое имя сохраняется |
| `uModelMatrix` | Мировая матрица `M` текущего пути, local → world |
| `uPerspectiveViewMatrix` | `P * V`, world → clip; имя сохраняется и для ортографической камеры |
| `uNormalMatrix` | `transpose(inverse(mat3(M)))`, normal-local → normal-world |
| `uEyePosition` | Мировая позиция камеры; предоставляется для обоих видов камер |
| `uLightPerspectiveViewMatrix` | `P_light * V_light`, world → light-clip |

`CameraUniforms` отвечает за согласованность матриц и позиции одной камеры.
Он не включает `M`: матрица объекта зависит от конкретного рисуемого экземпляра.
Нельзя добавлять `V` в `uModelMatrix` или передавать `M` вместо `L` в
`uTransformationMatrix`, сохраняя прежние имена без изменения контракта.

## 6. Нормали, свет и ориентация поверхностей

Стандартные шейдеры освещения работают в мировом пространстве. Положение
поверхности, положение наблюдателя, положения источников света, направления
света и нормали должны относиться к одному пространству.
Для направленного и прожекторного света `dir` задаёт направление распространения
света от источника; вектор от поверхности к источнику имеет противоположный смысл.

Нормаль преобразуется обратной транспонированной линейной частью `M` и
нормализуется перед расчётом освещения. После интерполяции нормаль также требует
нормализации. Перенос на нормаль не действует. Умножение только на `mat3(M)`
не заменяет normal matrix при неравномерном масштабе.

Это согласовано с использованием мировых координат в
[basic_shader.dart](../lib/src/shader/basic_shader.dart#L14) и вычислением
`copyNormalMatrix(_modelMatrix)` в
[Node.updateTransforms()](../lib/src/scene/node.dart#L39).
Комментарий TODO в этом методе сам по себе не является основанием добавлять
матрицу вида в normal matrix: это изменило бы пространство нормали.

Для треугольника с порядком вершин `(a, b, c)` геометрическая нормаль направлена
вдоль `cross(b - a, c - a)`. При взгляде со стороны этой нормали обход вершин
против часовой стрелки (CCW). Генераторы внешней поверхности должны согласовывать
этот порядок с выдаваемыми нормалями; внутренние поверхности задаются явно.

Отражение (`det(mat3(M)) < 0`) меняет ориентацию обхода. Преобразование нормали
не исправляет winding. При включённом отсечении граней требуется явное согласование
индексов или состояния определения лицевой стороны; автоматическое исправление
отражённых мешей не предполагается этим контрактом.

Двумерные контуры используют обычную плоскость XY с `Y` вверх.
Положительная ориентированная площадь соответствует CCW, как в
[getSignedArea()](../lib/src/polygon/basic.dart#L13).
Экранные DOM-координаты с `Y` вниз должны переводиться на границе браузерной
интеграции. Переворот изображения при загрузке текстуры (`flipY`) не меняет
мировые оси или направление взгляда камеры. Единицы viewport и преобразование
между CSS-размерами и drawing buffer относятся к пункту 1.3.

## 7. Орбитальное управление

Для сохранения существующей ориентации орбиты используется текущая формула
[setPosFromSpherical()](../lib/src/core/spatial.dart#L96):

```text
offset.x = radius * cos(elevation) * cos(azimuth)
offset.y = radius * sin(elevation)
offset.z = radius * cos(elevation) * sin(azimuth)
eye_world = target_world + offset
```

Здесь `elevation` — угол возвышения над плоскостью XZ. В текущем API он назван
`polar`, хотя отсчитывается не от оси `+Y`. Нулевой азимут размещает камеру
со стороны `+X`; увеличение азимута на четверть оборота перемещает её к `+Z`.
Азимут этой параметризации не равен положительному вращению вокруг `+Y`
по правилу правой руки. Не следует менять его знак при механическом переименовании.

`OrbitControls` вычисляет мировую позицию и затем ориентацию камеры относительно
мировой цели. Ограничение возвышения около полюсов предотвращает параллельность
направления взгляда и `upHint`. Скорость управления и единицы времени отдельно
определяются в пункте 1.3 и реализуются в фазе 4.

## 8. Импорт и скелетная анимация

Геометрия импортируется в локальные координаты объекта; мировое размещение
применяется матрицей `M` при отрисовке. Различие порядка хранения матриц формата
и `Matrix4` исправляется на границе импортёра, а не транспонированием всех матриц
движка. Например, текущий
[импорт Assimp](../lib/src/importer/assimp2json.dart#L110) транспонирует входную
матрицу; это не означает смены принятого порядка умножения.

Смена базиса входных координат является отдельной операцией. Для преобразования
базиса `B` точки преобразуются как `B * p`, а операторы в том же исходном базисе —
как `B * L * inverse(B)`. Нормали и winding также должны быть согласованы.
Базис нельзя угадывать по виду модели: нужны данные формата или явная настройка
импортёра. Эти правила не утверждают, что существующие импортёры уже выполняют
нормализацию любого внешнего формата.

`AnimatedSkeleton.globalTransforms` обозначает накопленные преобразования
в иерархии скелета, а не автоматически мировые матрицы сцены. Существующий порядок
[расчёта skinning](../lib/src/animation/skeleton_animation.dart#L72) сохраняется:

```text
G_bone    = G_parent * L_bone
S_bone    = globalOffsetTransform * G_bone * offsetTransform
p_skinned = sum(weight_i * S_bone_i * p_bind)
p_world   = M * p_skinned
```

Матрицы приведения импортированного скелета должны давать `p_skinned` в локальном
пространстве рисуемого объекта. Мировая матрица сцены применяется ровно один раз.
Названия `globalTransforms` и `globalOffsetTransform` не дают права повторно
включать в них мировое размещение узла, если шейдер затем применяет `M`.

| Индексы `rightX/rightY/rightZ` и аналогичные читают строки матрицы, несмотря на комментарии о столбцах | Извлекать базис мировой/локальной позы из столбцов; проверить помощники движения отдельно | Фаза 3 |
| `getViewMatrix()` копирует произвольный `Spatial.transform` | Камера возвращает обратную матрицу собственной мировой позы | Фаза 3 |
| `Orthographic.getUniforms()` не предоставляет `uEyePosition` | Единый `CameraUniforms` предоставляет согласованную мировую позицию независимо от проекции | Фаза 3 |
| `Node` уже умножает `parent * local`, но хранит результат последнего обхода | Сохранить порядок умножения; сделать контекст пути явным для мировых операций и кэшей | Фаза 5 |
| `uNormalMatrix` вычисляется из мировой матрицы | Сохранить пространство нормалей; проверить масштаб и нормализацию в шейдерах | Фазы 3 и 5 |
| Орбитальная камера задаёт позицию, затем заменяет её матрицу результатом `lookAt()` | `OrbitControls` изменяет отдельные положение и ориентацию камеры | Фаза 4 |

Исправление камеры может менять освещение, поведение движения после наведения
и изображения отдельных примеров. Это семантическая миграция, которую нельзя
свести к замене имён. В частности, нельзя просто начать обращать старую
`Spatial.transform`: после старого `lookAt()` она уже содержит view-матрицу.

В рендеринг-тестах
[_FixedCamera](../test/support/golden_scenes.dart#L312) хранит мировую позицию
отдельно и переопределяет оба метода камеры. Прохождение этих тестов не доказывает
корректность обычного `Spatial.lookAt()`.

## 10. Контрольные примеры

Результаты ниже являются ожидаемыми для целевого контракта. Примеры со вращением
используют математическую четверть оборота (`π/2`).

| Сценарий | Ожидаемый результат |
| --- | --- |
| `Rz(π/2) * (1, 0, 0, 0)` | `(0, 1, 0, 0)` |
| Родитель `T(10, 0, 0) * Rz(π/2)`, ребёнок `T(0, 2, 0)` | Мировое начало ребёнка `(8, 0, 0)`; его точка `(1, 0, 0)` попадает в `(8, 1, 0)` |
| Тот же ребёнок под другим родителем `T(-10, 0, 0)` | Мировое начало `(-10, 2, 0)`; результат первого пути не заменяет результат второго |
| Камера `eye=(0, 0, 10)`, `target=(0, 0, 0)`, `upHint=(0, 1, 0)` | Позиция остаётся `(0, 0, 10)`; начало мира в view имеет координаты `(0, 0, -10)` |
| Камера `eye=(4, 3, 6)`, цель в начале мира | Начало мира в view имеет координаты `(0, 0, -sqrt(61))`; `C * V` — единичная матрица |
| Камера в `(0, 0, 10)`, смотрящая на начало; `near=1`, `far=11` | Мировая точка `(0, 0, 9)` даёт `z_ndc=-1`, точка `(0, 0, -1)` — `+1` для обеих проекций |
| `M = scale(2, 1, 1)`, нормаль `(1, 1, 0)` | До нормализации получается `(0.5, 1, 0)`, перпендикулярная преобразованной касательной `(2, -1, 0)` |
| Орбита радиуса 2, возвышение 0 | При азимуте 0 смещение `(2, 0, 0)`, при `π/2` — `(0, 0, 2)` |

Формулы и числовые примеры сверены локально с установленным `vector_math`:
156 скалярных сравнений с допуском `1e-5`, включая хранение по столбцам,
`setViewMatrix`, обе проекции и `copyNormalMatrix`. Этот допуск относится
к проверке примеров, а не устанавливает универсальный допуск публичного API.
Проверка не является реализацией новых классов или регрессионными тестами
текущей камеры.

При реализации необходимо добавить постоянные проверки:

- [ ] Сохранение позиции при `lookAt()` и согласованность `uEyePosition` для обоих типов камер.
- [ ] Порядок `parent * local`, локальные направления движения и независимые результаты двух путей DAG.
- [ ] Отказ от неоднозначных мировых операций и циклов в графе.
- [ ] Наведение с произвольным `upHint`; отказ на вырожденных входах без изменения предыдущего состояния.
- [ ] Отказ от неортонормальной позы камеры и вырожденных обратных преобразований.
- [ ] Normal matrix при неравномерном масштабе и согласованность нормалей со светом в мировом пространстве.
- [ ] Сохранение ориентации орбиты и применение мировой матрицы к результату skinning ровно один раз.
