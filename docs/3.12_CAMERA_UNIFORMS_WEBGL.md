# 3.12. Проверка uniforms новой камеры в WebGL

Пункт **3.12** [плана рефакторинга](../REFACTORING_PLAN.md) добавляет
проверку значений, действительно загруженных в WebGL через `CameraUniforms`.
Реализация рендера, публичные API и математические импорты не меняются.

## Что проверяется

[`camera_uniforms_webgl_test.dart`](../test/camera_uniforms_webgl_test.dart)
импортирует публичный `chronosgl.dart`, создаёт WebGL2-контекст и настоящую
программу с активными `uPerspectiveViewMatrix`, `uEyePosition` и `uModelMatrix`.
Vertex shader использует обе матрицы, fragment shader — все три компонента
мировой позиции глаза.

После `RenderProgram.draw()` или `RenderPhase.draw()` тест получает текущую
WebGL-программу и читает uniforms через `getUniform()`. Результат
`JSFloat32Array` переводится в Dart typed data через `.toDart`.
Сравниваются все 16 коэффициентов `uPerspectiveViewMatrix` и все три
координаты `uEyePosition`, а в сцене — ещё и отдельная `uModelMatrix`.
Проверяются активность locations, отсутствие незаданных inputs и WebGL-ошибок.

Эталон не берётся из `CameraUniforms.getUniforms()` или
`Camera.viewProjectionMatrix`: проекция рассчитывается функциями
`vector_math`, вид при наведении — `makeViewMatrix()` по заданным eye/target.
Для явного изменения ориентации используется известная перестановка осей
кватернионом `(1, 1, 1, 1)` с независимо заданной матрицей вида.
Порядок произведения остаётся `P * V`, без транспонирования и без матрицы
модели. Абсолютный допуск сравнения — `2e-5` для выбранных Float32-значений.

## Сценарии

| Сценарий | Тестов | Проверки |
| --- | ---: | --- |
| Прямой `draw()` для перспективной и ортографической камеры | 2 | Глаз `(0, 0, 10)` после наведения на начало координат, перенос в другую мировую позицию, повторное наведение без переноса, `setRotation`, новые параметры проекции и испорченный снимок CPU перед повторной загрузкой |
| `Scene` с преобразованным родителем и дочерним мешем | 2 | `uModelMatrix = parent * local` изменяется при движении объекта, `P * V` и мировой глаз сохраняются; последующее движение камеры обновляет её uniforms |
| Чередование двух адаптеров в одной программе | 1 | Перспективная и ортографическая камеры с одинаковым именем группы не оставляют значения предыдущего draw |

Перспективная проверка меняет FOV, aspect, near и far. Ортографическая
использует несимметричные границы и отрицательный near, затем заменяет
границы и clipping distances. Во всех случаях следующий draw получает
актуальные значения без отдельного обновления адаптера.

Каждый тест освобождает созданные mesh/program и завершает WebGL-контекст.
Тесты 3.9 по-прежнему отдельно проверяют владение снимками, ошибки и pixels;
новый набор дополняет их непосредственным чтением uniforms из WebGL.

## Запуск и результат

Новый файл включён в preset `all`. Для проверки пункта используются только
пять выбранных тестов, без полного preset:

```sh
dart test -p golden_chrome test/camera_uniforms_webgl_test.dart
dart test -p golden_chrome -c dart2wasm test/camera_uniforms_webgl_test.dart
```

Если Dart не находит Chrome/Chromium, задайте `CHROME_EXECUTABLE`.
В текущем окружении использован `/usr/bin/chromium` с существующим
профилем `golden_chrome` и SwiftShader.

Все **5 тестов прошли в JavaScript и Wasm**. Дополнительный Wasm-запуск
проверяет тот же путь загрузки и чтения typed arrays через JavaScript interop.
`dart analyze test/camera_uniforms_webgl_test.dart` завершился без замечаний.

## Итог фазы 3

Пункт 3.12 завершает последний критерий фазы: математическая часть работает
на VM, адаптер передаёт согласованные значения в браузерный рендер.
[Проверка импорта 3.10](3.10_VM_MATH_IMPORTS.md) компилирует и запускает
самостоятельную VM-программу; [выбранные наборы 3.11](3.11_VM_CAMERA_TESTS.md)
подтверждают 83 математических теста на VM; текущий набор проверяет WebGL
для обеих камер в JavaScript и Wasm. Результаты 3.10–3.11 сохранены из
предыдущих шагов: математический код в 3.12 не менялся.

Все задачи и критерии фазы 3 выполнены. Контроллеры камеры, обработка ввода
и resize относятся к фазе 4. Полные проверки, сборки примеров и rendering
goldens в рамках 3.12 не запускались; эталонные изображения не менялись.
