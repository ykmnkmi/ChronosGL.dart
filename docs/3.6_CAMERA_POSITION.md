# 3.6. Сохранение положения камеры и мировой uEyePosition

Пункт **3.6** [плана рефакторинга](../REFACTORING_PLAN.md) исправляет
[ошибку из 1.5](1.5_CAMERA_POSITION_REPRODUCTION.md). `Spatial.lookAt()` больше
не заменяет положение камеры переносом матрицы вида. Новые `PerspectiveCamera`
и `OrthographicCamera` уже соблюдали этот контракт; их реализация не меняется,
добавлены проверки повторного наведения и наведения после перемещения.

## Состояние и матрица вида

`Spatial.transform` теперь всегда имеет смысл local → parent. Для камеры без
родителя это camera-local → world. `lookAt(target, [up])` строит жёсткую
ориентацию общей функцией `lookAtRotation`, направляет локальную −Z к цели
и сохраняет перенос. Цель и up заданы в пространстве родителя, для камеры —
в мировом. Наведение однократное: цель не сохраняется и не отслеживается.

```dart
final camera = Spatial('camera')..setPos(0, 0, 10);
camera.lookAt(vm.Vector3.zero());
// getPos() и getEyePosition() равны (0, 0, 10).
final view = vm.Matrix4.zero();
camera.getViewMatrix(view);
// view переводит (0, 0, 10) в (0, 0, 0).
```

`getViewMatrix(out)` вычисляет `inverse(transform)` и копирует результат в
`out`, не меняя позу. Это справедливо и до первого `lookAt`, после прямого
изменения матрицы, переноса или вращения. Нельзя использовать сам `transform`
как выходное хранилище: это даёт `ArgumentError`. Вырожденная матрица или
непредставимый конечный inverse дают `StateError`, сохраняя позу и выход.

`lookAt` использует проверки нового `Camera`: конечные значения, несовпадающая
цель, ненулевой up и синус угла с направлением взгляда больше `1e-6`.
Ошибки дают `ArgumentError` без частичной записи. Legacy-метод, как и прежде,
заменяет линейную часть жёстким вращением, отбрасывая масштаб и shear.
Для сохранения поддерживаемого масштаба следует использовать `Transform`.

## Направления, движение и uniforms

Направления теперь читаются из столбцов позы: right — `0,1,2`, up — `4,5,6`,
back — `8,9,10`. `moveForward/Backward/Right/Left/Up/Down` используют эти же
столбцы. При прямой записи масштабированной матрицы длина шага по-прежнему
зависит от её масштаба; этот legacy API не заменяет движение `Transform`.
`lookUp/Down`, `lookLeft/Right`, `rollLeft/Right` вращают вокруг локальных
X, Y, Z, не перемещая камеру; up/left используют положительный угол.
Это сохраняет цель `OrbitCamera` при ненулевом roll.

`Perspective` и `Orthographic` публикуют:

```text
uEyePosition = camera.getEyePosition()       мировая позиция
uPerspectiveViewMatrix = projection * view   world → clip
```

У `Perspective` существующий вызов `getEyePosition()` теперь получает
исправленное положение; у `Orthographic` добавлен тот же uniform.
Оба адаптера продолжают вызывать виртуальные методы, поддерживая специальные
камеры с собственными `getViewMatrix` и `getEyePosition` (включая golden-сцены).
`Perspective.updateCamera` меняет источник обоих значений при следующем чтении.

## Миграция и границы

Код, считавший `Spatial.transform` матрицей вида, должен перейти на
`getViewMatrix(out)`. При импорте готовой view-матрицы её нужно сначала обратить.
Для `Node.lookAt` цель задаётся в пространстве родителя, локальная позиция
сохраняется, а обход сцены по-прежнему вычисляет `parent * local`.
Это исправление поведения может изменить сцены, зависевшие от старой ошибки;
подробности также записаны в [MIGRATION.md](../MIGRATION.md).

Legacy-матрица и рабочие векторы остаются изменяемыми; `getPos()` не возвращает
снимок. Для сохранения значения нужна копия. Камера с родителем не поддерживается
этим API. Новый адаптер `CameraUniforms` остаётся задачей 3.9, правила доступа
к матрицам — 3.7, итоговые проверки новой модели и GPU uniforms — 3.11–3.12.
Зависимость управления орбитой от частоты кадров остаётся задачей фазы 4.

## Проверки

[`camera_look_at_test.dart`](../test/camera_look_at_test.dart) содержит 4 теста
для новых камер: повторное наведение на разные цели с нестандартным up,
сохранение исходных векторов, согласованность с независимым `makeViewMatrix`,
`P * V` и наведение после перемещения. Набор работает на VM, JavaScript и Wasm.

[`camera_position_reproduction_test.dart`](../test/camera_position_reproduction_test.dart)
содержит 14 браузерных регрессий: исходный сценарий, вид до наведения,
согласованность с новой камерой, движение и локальные вращения, атомарность
ошибок, оба набора uniforms, виртуальные методы, замена камеры, повторные
кадры орбиты с roll и `Node` под преобразованным родителем.

```sh
dart analyze
dart test test/camera_look_at_test.dart
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
dart run build_runner build --output=example:build/example
dart run tool/goldens.dart --self-check
```

Результаты на Dart 3.14.0: анализ без замечаний, 4 новых VM-теста проходят,
полный VM/JavaScript-прогон — 454 теста, прогон с Wasm — 452 теста (preset
также запускает VM-наборы; два legacy DOM-теста предназначены только для JS).
Все 18 проверок двух файлов проходят в JavaScript и Wasm. Сборка примеров
и тестовых bootstraps завершена успешно. Rendering goldens совпадают с прежними
эталонами; self-check подтверждает обнаружение намеренного изменения цвета.
Эталонные изображения не обновлялись.
