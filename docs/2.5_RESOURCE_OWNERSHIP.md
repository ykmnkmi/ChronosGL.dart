# 2.5. Собственные и заимствованные GPU-ресурсы

Пункт **2.5** [плана рефакторинга](../REFACTORING_PLAN.md) выполнен: добавлена явная
передача владения внешними буферами и текстурами. Переданные ресурсы по умолчанию
заимствуются. Ресурсы, созданные для внутренних нужд объекта, принадлежат ему.
Фабрики, возвращающие готовый ресурс, передают его вызывающему коду.

## API и совместимость

| Операция | Кто освобождает ресурс |
| --- | --- |
| `MeshData.addVertices/addAttribute/addFaces` | Меш освобождает созданные буферы и свой VAO |
| `changeAttributeBuffer(name, buffer)` | Внешний владелец буфера |
| `changeAttributeBuffer(name, buffer, takeOwnership: true)` | Меш после успешного подключения |
| `Texture` и наследники | Обёртка освобождает созданный texture handle; DOM-источник заимствуется |
| `RenderProgram` | Программа освобождает свой GPU handle; меши, материалы и текстуры заимствуются |
| `Framebuffer(cgl, color, ...)` | Framebuffer освобождает только свой handle |
| `Framebuffer.withAttachments(cgl, ..., takeOwnership: [...])` | Framebuffer освобождает свой handle и перечисленные текстуры |
| `Framebuffer.defaultFramebuffer()` / `.effect()` | Framebuffer освобождает все созданные им attachments |
| `Framebuffer.screen()` | Собственного GPU handle нет |
| `ChronosGL.create*()`, `RenderProgram.makeMeshData()`, фабрики мешей | Вызывающий код владеет возвращённым ресурсом |

Существующие вызовы сохраняют режим владения. Новый конструктор framebuffer
использует именованные параметры; старый конструктор с позиционными параметрами
сохранён. `withAttachments` остаётся generative и доступен наследникам.

## Буферы меша

```dart
// Буфер создан вызывающим кодом и ещё не принадлежит другому мешу.
mesh.changeAttributeBuffer(aPosition, buffer, takeOwnership: true);

// Другой потребитель только заимствует тот же буфер.
otherMesh.changeAttributeBuffer(aPosition, buffer);
otherMesh.dispose();
mesh.dispose(); // Удаляет buffer после завершения работы потребителя.
```

Передача фиксируется после успешной настройки атрибута и проверки ошибки WebGL.
Неизвестный атрибут даёт `ArgumentError`, освобождённый меш и ошибка WebGL —
`StateError`. При исключении новый буфер не записывается в слот и не принимается
во владение. Собственные буферы учитываются независимо от слотов. После
[пункта 2.6](2.6_RESOURCE_REPLACEMENT.md) временный буфер при неудачном `add*()`
удаляется сразу, а прежняя рабочая конфигурация сохраняется.

Повторное подключение собственного буфера с `takeOwnership: false` не отказывается
от владения. Один handle может использоваться несколькими атрибутами и удаляется
один раз. `clearData()` освобождает также явно переданные буферы; заимствованные
отключаются и остаются живыми. `getBuffer()` возвращает заимствованный handle.

Для сырых `GlBuffer` нет глобального реестра владельцев. Вызывающий код обязан
не передавать один буфер двум мешам и не передавать чужой буфер, полученный
через `getBuffer()`. Параметр `takeOwnership` не отсоединяет прежнего владельца.

## Текстуры framebuffer

```dart
final target = Framebuffer.withAttachments(
  cgl,
  colorTexture: localColor,
  depthTexture: sharedDepth,
  takeOwnership: [localColor],
);
target.dispose(); // localColor освобождается, sharedDepth сохраняется.
```

`takeOwnership` — перечисление конкретных attachments, поэтому можно сочетать
собственные и общие текстуры. Список копируется до создания framebuffer;
его последующее изменение ничего не меняет. Повторы и несколько слотов одной
текстуры учитываются по идентичности объекта и освобождаются один раз.
Попытка передать текстуру, не указанную в attachments, даёт `ArgumentError`.

У текстуры учитывается framebuffer-владелец, включая фабричные attachments.
Попытка передать её второму framebuffer даёт `StateError` до создания нового
handle. Заимствование этой же текстуры разрешено. Передача владения означает,
что вызывающий код больше не освобождает её самостоятельно.

Оба внешних конструктора проверяют состояние, тип `TEXTURE_2D` и WebGL-контекст
attachments до выделения framebuffer. Освобождённая текстура даёт `StateError`,
чужой контекст или неподходящий тип — `ArgumentError`. Разные обёртки `ChronosGL`
одного браузерного контекста совместимы.

Владение внешними текстурами принимается только после полной успешной
инициализации, включая проверку полноты и сброс привязки. При ошибке удаляется
незавершённый framebuffer, восстанавливаются прежние READ/DRAW bindings,
а все внешние текстуры остаются у вызывающего кода. После ошибки можно повторить
передачу. Фабричные текстуры, напротив, принадлежат framebuffer сразу после
создания и очищаются при ошибках согласно [пункту 2.4](2.4_RESOURCE_CREATION_FAILURES.md).

## Границы пункта

Владение ресурсами не связано с количеством потребителей. Перед освобождением
владелец должен дождаться окончания их работы. `dispose()` не вводит подсчёт
ссылок; удаление связи сцены не передаёт и не освобождает общий меш или материал.
Материалы и группы uniforms заимствуют ресурсы, содержащиеся в uniforms.

Учёт собственных ресурсов независим от изменяемых слотов. Обновление по
[пункту 2.6](2.6_RESOURCE_REPLACEMENT.md): замена последнего использующего ресурс
слота освобождает вытесненный собственный ресурс сразу после фиксации замены.
Присваивание attachments framebuffer теперь обновляет и GPU-привязки; добавлен
`replaceAttachments()` с явным владением. Ошибка подготовки сохраняет старые
ресурсы и привязки; ошибка удаления старого ресурса не отменяет уже принятую
новую конфигурацию и владение.
Составные помощники, управление вводом и диагностикой реализуются в своих
пунктах плана; здесь не добавляется рекурсивное освобождение графа сцены.

## Проверки

[Браузерные тесты](../test/resource_ownership_test.dart) включены в preset `all`.
Проверяются передача и заимствование, смешанное владение, повторное подключение,
aliases, `clearData()`, ошибки принятия, запрет двух framebuffer-владельцев,
несовместимые и освобождённые текстуры, восстановление bindings и повторная
передача после сбоя. Используются настоящий WebGL2, счётчики удалений,
проверки живых handles и пикселей после удаления заимствующего потребителя.

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

Все 30 новых тестов проходят в JavaScript и Wasm. Полные наборы также проходят:
202 VM/JavaScript-теста и 200 VM/Wasm-тестов, включая эталонные изображения
рендера. Два legacy DOM-теста предназначены только для JavaScript.
`dart analyze` — без замечаний; форматирование изменённых Dart-файлов проверено.
