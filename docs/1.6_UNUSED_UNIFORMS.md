# 1.6. Обработка неиспользуемых uniforms в RenderProgram

Исправление выполнено в [RenderProgram](../lib/src/core/render_program.dart).
Поведение закреплено в [браузерных тестах](../test/render_program_uniforms_test.dart),
включённых в preset `all`.

## Причина ошибки

Объявленный в шейдере uniform может быть удалён оптимизатором, если он не влияет
на результат программы. В этом случае `getUniformLocation()` возвращает `null`.
Ранее конструктор `RenderProgram` применял `!` к результату для каждого uniform
вершинного и фрагментного шейдеров. Создание корректной программы завершалось
ошибкой `Null check operator used on a null value` ещё до отрисовки.

Минимальный сценарий при уже созданном WebGL2-контексте `cgl`:

```dart
final vertex = ShaderObject('unused-v')
  ..addAttributeVars([aPosition])
  ..addUniformVars([uTime])
  ..setBodyWithMain(['gl_Position = vec4($aPosition, 1.0);']);
final fragment = ShaderObject('unused-f')
  ..addUniformVars([uTexture])
  ..setBodyWithMain(['$oFragColor = vec4(1.0);']);

final program = RenderProgram('unused', cgl, vertex, fragment);
```

Имена доступны из `package:chronosgl/chronosgl.dart`. Объявления `uTime`
и `uTexture` не используются в телах шейдеров. После исправления программа
создаётся, а `program.uninitializedInputs()` содержит только `aPosition`.
Полный сценарий с созданием контекста, меша и чтением пикселей находится в тесте.

## Поведение после исправления

Конструктор объединяет имена uniforms обоих шейдеров в множество и запрашивает
location каждого имени один раз у связанной программы. В `_uniformLocations`
попадают только ненулевые locations.

- Uniform с отсутствующим location не требует значения при `draw()` и не
  включается в `uninitializedInputs()`.
- Если значение такого uniform передано в `UniformGroup`, оно пропускается
  до преобразования типа и загрузки в GPU. Неактивный sampler также пропускается
  без привязки текстуры и выделения текстурного блока.
- Uniform, объявленный в обоих шейдерах и используемый хотя бы в одном из них,
  обрабатывается по location связанной программы.
- Активные uniforms загружаются при отрисовке. Если активное значение не передано,
  оно по-прежнему попадает в `uninitializedInputs()` и сообщение диагностики.

## Регрессионные проверки

Три теста проверяют неиспользуемый `uTime` в вершинном шейдере, фрагментном шейдере
и обоих сразу. В каждом случае активный `uScale` объявлен в обоих шейдерах,
но используется только в вершинном. Пропущенный `uColor` остаётся в диагностике;
после его передачи пиксели становятся красными, а при обновлении — зелёными.
Передача `Object()` вместо значения неактивного `uTime` проверяет, что оно
пропускается до преобразования типа.

Четвёртый тест проверяет программу, у которой удалены все uniforms, включая
sampler `uTexture`. Отрисовка без групп uniforms и с переданными неактивными
значениями даёт белое изображение без неинициализированных входов.

Тесты используют настоящий WebGL2-контекст, читают все пиксели canvas размером
2 × 2 и проверяют отсутствие ошибок WebGL. Контекст освобождается после теста.
Сообщения `uninitialized inputs: [uColor]` ожидаемы в сценариях намеренного
пропуска активного значения.

## Запуск и результат

Из корня проекта с установленными зависимостями и Chrome:

```sh
dart test -p golden_chrome test/render_program_uniforms_test.dart
dart test -p golden_chrome -c dart2wasm test/render_program_uniforms_test.dart
```

Платформа `golden_chrome` определена в [dart_test.yaml](../dart_test.yaml)
и использует SwiftShader. Полные проверки:

```sh
dart analyze
dart test -P all
dart test -P all -p golden_chrome -c dart2wasm
```

При выполнении пункта 1.6 все четыре новых теста сначала воспроизвели ошибку
на исходном коде с JavaScript-компиляцией. После исправления статический анализ
завершился без замечаний; прошли 60 тестов VM/JavaScript и 58 тестов VM/Wasm,
включая новые проверки и сравнение изображений с эталонами.
