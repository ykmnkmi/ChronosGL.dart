# 7.1–7.12. Поддерживаемый публичный API

Результат фазы **7** из [плана рефакторинга](../REFACTORING_PLAN.md).
Состав экспортов определяется публичными файлами `lib/*.dart`; реализация
в `lib/src/` не является поддерживаемой точкой входа. Исходная
[карта API](1.1_PUBLIC_API_MAP.md) остаётся историческим предложением;
этот документ описывает реализованную границу.

## Модули и зависимости

| Импорт `package:chronosgl/…` | Назначение | Dart VM |
| --- | --- | --- |
| `core.dart` | `Transform`, неизменяемый `Color`, палитра | Да |
| `camera.dart` | Камеры и математические проекции | Да |
| `geometry.dart` | CPU-геометрия, формы, контуры и триангуляция | Да |
| `animation.dart` | Кости, ключевые кадры, расчёт поз | Да |
| `importers.dart` | Разбор Wavefront, ThreeJS JSON и Assimp JSON | Да |
| `shaders.dart` | `ShaderObject`, стадии, метаданные, GLSL | Да |
| `webgl.dart` | `ChronosGL`, `Gl*`, числовые константы WebGL2 | Нет |
| `render.dart` | Программы, GPU-меши, материалы, uniforms, текстуры, framebuffer, свет | Нет |
| `mesh.dart` | Дополнительный узкий импорт GPU-мешей, загрузки и фабрик | Нет |
| `scene.dart` | `Node`, `GroupNode`, `MeshNode`, `RenderBatch`, `RenderPass` | Нет |
| `shadows.dart` | Расчёт карт теней | Нет |
| `web.dart` | Ввод, контроллеры, viewport, URL-загрузка | Нет |
| `debug.dart` | Панели статистики и визуализаторы | Нет |

`chronosgl.dart` объединяет поддерживаемые рабочие модули. Диагностика
подключается отдельно через `debug.dart`. CPU-модули не импортируют DOM,
`dart:js_interop` или WebGL транзитивно. В частности, импортеры и генераторы
шейдеров больше не используют браузерную библиотеку `src/core/lib.dart`.
`NamedEntity`, логирование и legacy `Spatial` пока принадлежат `render.dart`;
их перенос в математический `core.dart` не требуется для использования камер
и геометрии на VM.

Экспорты реализаций используют явные списки `show`: добавление нового
внутреннего объявления не расширяет API автоматически. Общий импорт
реэкспортирует публичные модули и не экспортирует `src` напрямую.

## Стадии шейдеров и uniforms

Для новых шейдеров стадия задаётся явно:

```dart
final vertex = ShaderObject.create(
  name: 'vertex without attributes',
  stage: ShaderStage.vertex,
)..setBodyWithMain(['gl_Position = vec4(0.0, 0.0, 0.0, 1.0);']);
final fragment = ShaderObject.fragment('fragment')
  ..setBodyWithMain(['$oFragColor = vec4(1.0);']);
```

Также доступен `ShaderObject.vertex(name)`. Вершинный шейдер без атрибутов
не превращается во фрагментный. Только устаревший `ShaderObject(name)`
сохраняет определение стадии по атрибутам. Программа проверяет порядок
стадий и наличие завершённых исходников до компиляции.

Метаданные интерфейса добавляются до установки тела. После генерации тела
изменение интерфейса или повторная установка исходников даёт `StateError`.
Коллекции атрибутов, uniforms, varyings и layout доступны для чтения.

`UniformKey<T>` связывает каноническое строковое имя с типом Dart;
`UniformKeys` содержит готовые ключи для матриц, цвета, времени, текстур и
других распространённых uniforms:

```dart
final material = Material('surface')
  ..set(UniformKeys.color, colorWhite.toVector3());
material.force(UniformKeys.color, colorBlue.toVector3());
final color = material.get(UniformKeys.color);
```

Для пользовательского имени сначала вызывается `introduceNewShaderVar`,
затем создаётся `UniformKey<T>`. При установке проверяется тип Dart и
форма зарегистрированного GLSL-значения. Массивы матриц и float-значений
передаются как плоский `Float32List`, массивы int — как `Int32List`.

Строковые `u*` остаются константами для GLSL и для переходных
`setUniform`/`forceUniform`. `set` и `setUniform` не заменяют существующее
значение: повторная установка даёт `StateError`. Для замены служат
`force` и `forceUniform`. Значения заимствованы, а `getUniforms()`
возвращает неизменяемый снимок отображения. Для изменения состава доступны
`addUniforms`, `removeUniform`, `clearUniforms`. Исключение — `CameraUniforms`:
он сохраняет прежний контракт свежей изменяемой карты с независимыми
снимками камеры. Её изменение не меняет состояние адаптера.

## Именованные параметры и единицы

Сложные конструкторы получили именованные точки входа:

- `RenderProgram.create(name:, context:, vertexShader:, fragmentShader:)`;
- `RenderBatch.named`, `RenderPass.named`;
- `TypedTexture.allocate`, `TypedTextureMutable.allocate`;
- `PointLight.named`, `DirectionalLight.named`, `SpotLight.named`;
- `Bone.named`, `BoneAnimation.keyframes`, `SkeletalAnimation.named`;
- `OrbitControls.forCamera`, `CanvasViewport.forCanvas`;
- типизированные конструкторы браузерных объектов из следующего раздела.

Старые сигнатуры сохраняются там, где смысл операции не изменён. Полная
[таблица перехода](../MIGRATION.md#supported-public-api-refactoring-phase-7)
содержит соответствия и изменения коллекций.

Углы камер и света выражены в радианах. `SpotLight.named.angleRadians`
обозначает половинный угол конуса. Положение, размеры, расстояния near/far,
радиус/дальность света и размер области направленного света используют
согласованные единицы мира приложения. Viewport использует пиксели
framebuffer; CSS-размеры и плотность пикселей отделены от них.

`OrbitControls.update` получает прошедшие секунды; `FpsPanel` получает
монотонные временные метки в миллисекундах. Низкоуровневые ключевые кадры,
длительность и время выборки анимации используют общую единицу,
выбранную вызывающим кодом. Конвенции времени старых импортёров в этой
фазе не нормализуются; их различия зафиксированы в
[аудите единиц](1.3_UNITS_CONVENTIONS.md#часы-интервал-и-анимация).

## Браузерные границы

Для `package:web` доступны статически типизированные точки входа:

- `ChronosGL.fromCanvas(web.HTMLCanvasElement)`;
- `Keyboard.forTarget(web.EventTarget)`, `Mouse.forTarget(web.EventTarget)`;
- `CanvasViewport.forCanvas(canvas: web.HTMLCanvasElement, …)`;
- `OrbitControls.forCamera(eventTarget: web.EventTarget, …)`;
- `ImageTexture.fromImage`, `.fromCanvas`, `.fromVideo`, `.fromImageBitmap`;
- `CubeTexture.fromImages(images: List<web.HTMLImageElement>, …)`;
- `StatsPanel.attach(root: web.HTMLElement, …)`, `FpsPanel.attach(…)`.

Переданные DOM-объекты заимствуются. Старые конструкторы с `Object`
обозначены как legacy-граница: объекты SDK `dart:html` поддерживаются
только при компиляции в JavaScript. Для JavaScript и Wasm следует
использовать новые конструкторы с `package:web`.
Переходный Object-конструктор `OrbitCamera` также помечен deprecated;
для нового кода используются математическая камера и `OrbitControls.forCamera`.

## Ошибки, коллекции и исключённые объявления

| Ошибка | Смысл |
| --- | --- |
| `ArgumentError` | Неверное значение или несовместимые аргументы |
| `StateError` | Неверное состояние, повторная установка, использование после освобождения |
| `UnsupportedError` | Операция не поддерживается данным видом объекта |
| `ShaderCompilationException` | Ошибка компиляции GLSL или линковки программы |

`ShaderCompilationException` содержит сообщение драйвера, исходник и
стадию; для ошибки линковки стадия отсутствует. Публичные контракты
проверяются во время выполнения независимо от включения assertions.
Строковые исключения исключены.
Управляющие параметры и активные uniforms проверяются до изменения состояния
WebGL, включая значения, переданные через переходные строковые методы установки.
`GpuMesh.changeFaces` требует буфер индексов, созданный через `addFaces`.
До его создания, в том числе после `clearData()`, метод выдаёт `StateError`
без изменения CPU-данных и bindings WebGL.

Списки shader-интерфейса, отображения layout и uniforms, таблица easing и
список дорожек анимации защищены от структурного изменения через чтение.
Для редактирования используются методы владельцев. Списки дочерних узлов,
корней и uniforms пакета отрисовки остаются редактируемыми между проходами;
циклы проверяются при обходе. CPU-геометрия остаётся
редактируемой; перед загрузкой вызывается `validate()`.

Из поддерживаемых экспортов исключены незавершённые `MidiInput`,
`findBridge` и GPU-помощник `extractWireframe`. Для wireframe следует
передавать исходную CPU-геометрию в `uploadWireframeGeometry`.
Реализованной замены MIDI и построению мостов отверстий пока нет.

Внутренними считаются `UnknownEntity`, `kUnknownEntity`, `Face1`, `Face2`,
`Edge3`, `hashVector3`, индексы колонок `Spatial`, коды префиксов shader-имён,
таблицы икосаэдра и его UV-помощники, `noWebglMessage`, `textureChannelsByType`,
`isCubeChildTextureType`, `drawRecursively`, `getOrthogonalVector3`.
Для обычной работы используются `Face3`/`Face4`, фабрики геометрии и
методы сцены. Исправленное имя `coneGeometryWireframeFriendly` имеет
именованные параметры; старое `coneGeometryWireframeFrienly`
остаётся переходной обёрткой.

## Целевые проверки

- `dart test -p vm test/public_cpu_imports_test.dart`: совместная работа шести
  CPU-точек входа без браузерных зависимостей.
- `dart analyze lib/core.dart lib/camera.dart lib/geometry.dart lib/animation.dart lib/importers.dart lib/shaders.dart lib/webgl.dart lib/mesh.dart lib/render.dart lib/scene.dart lib/web.dart lib/shadows.dart lib/debug.dart lib/chronosgl.dart`:
  корректность списков поддерживаемых экспортов.
- `dart test -p vm test/public_exports_test.dart`: проверка анализатором
  доступности поддерживаемых имён и отсутствия внутренних и диагностических
  сущностей в общем импорте.
- `dart test -p golden_chrome test/public_render_api_test.dart`: отрисовка
  сцены, типизированный ввод и диагностика через публичные модули без `src`.
- `dart test -p golden_chrome -c dart2wasm test/public_render_api_test.dart test/runtime_contracts_web_test.dart test/uniform_api_test.dart`:
  границы браузерных объектов, uniforms и ошибки в Wasm.

Дополнительные проверки фазы покрывают shader API, ошибки и сцену с
диагностикой через публичные импорты. Полная матрица и миграция всех
примеров относятся к фазе 8.
