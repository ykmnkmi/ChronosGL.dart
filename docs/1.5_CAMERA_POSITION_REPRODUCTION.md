# 1.5. Воспроизведение потери мировой позиции камеры

Сохранено в [браузерном тесте](../test/camera_position_reproduction_test.dart).
Исправление отложено до фазы 3, пунктов 3.4–3.6; код библиотеки не меняется.

## Запуск

Из корня проекта с установленными зависимостями и Chrome:

```sh
dart test --platform chrome test/camera_position_reproduction_test.dart
```

Файл также включён в существующий preset `all` (`dart test --preset all`).
Браузер нужен из-за импортов текущего core; canvas, WebGL-контекст,
шейдеры и изображение для этого воспроизведения не нужны.

## Минимальный сценарий

```dart
final camera = Spatial('camera')..setPos(0, 0, 10);
camera.lookAt(vm.Vector3.zero());
final position = vm.Vector3.copy(camera.getPos());
final uniforms = Perspective(camera, 0.1, 100).getUniforms();
final eye = uniforms[uEyePosition] as vm.Vector3;
```

Здесь `vm` — импорт `package:vector_math/vector_math.dart`; `Spatial`,
`Perspective` и `uEyePosition` доступны из `package:chronosgl/src/core/lib.dart`.

| Значение после наведения на начало координат | Ожидается | Сейчас |
| --- | --- | --- |
| `camera.getPos()` | `(0, 0, 10)` | `(0, 0, -10)` |
| `camera.getEyePosition()` | `(0, 0, 10)` | `(0, 0, -10)` |
| `Perspective.getUniforms()[uEyePosition]` | `(0, 0, 10)` | `(0, 0, -10)` |

В [Spatial](../lib/src/core/spatial.dart) `setPos()` записывает мировую
позицию в перенос `transform`, но `lookAt()` вызывает
`vm.setViewMatrix(transform, getPos(), target, up)` и заменяет его матрицей
вида. `getPos()` продолжает читать элементы 12–14, а `getEyePosition()`
делегирует ему. [Perspective](../lib/src/core/projection.dart) передаёт это
значение в `uEyePosition` без преобразования. Для выбранной камеры перенос
матрицы вида равен `(0, 0, -10)`, хотя наблюдатель находится в `(0, 0, 10)`.
Сама матрица вида корректно переводит исходную позицию наблюдателя в начало
координат — это отдельно проверяется, чтобы отличать ошибку хранения позиции
от ошибки построения матрицы вида.

Снимок исходной позиции копируется: `getPos()` возвращает переиспользуемый
рабочий вектор, и сохранение одной ссылки не фиксирует значение до `lookAt()`.

## Переход к регрессионной проверке

Оба теста намеренно проверяют **текущее ошибочное поведение** и проходят,
пока ошибка воспроизводится. Это фиксация отложенной ошибки, а не утверждение
правильного контракта; обязательные проверки не оставляются падающими или
пропущенными. Проверка uniforms охватывает значение, выдаваемое адаптером,
а не чтение uniform из GPU-программы.

В пункте 3.6 нужно заменить ожидания `(0, 0, -10)` на `(0, 0, 10)`,
адаптировать тесты к новой модели камеры и убрать пометки `Known bug`.
Проверку матрицы вида сохранить. Математическую часть перенести на VM
в пункте 3.11, а браузерную проверку нового адаптера uniforms выполнить
в пункте 3.12. Контракт описан в
[соглашениях о координатах](1.2_COORDINATE_CONVENTIONS.md).
