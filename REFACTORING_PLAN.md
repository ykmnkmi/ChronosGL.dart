# План рефакторинга ChronosGL 5.0.0

Цель: выделить полноценную модель камер, разделить обязанности внутренних
компонентов, вынести демонстрационный код из библиотеки и оформить поддерживаемый
публичный API.

Отмечать выполненные пункты заменой `[ ]` на `[x]`. Фаза считается завершённой,
когда выполнены её задачи и критерии готовности. Текущий прогресс отражён ниже;
результаты предыдущего аудита служат исходными данными. Подготовка документов
отмечается после выполнения, а принятие предложений фиксируется отдельно на ревью.

Задачи имеют постоянные номера `x.y`: номер фазы и номер задачи внутри неё.
Документы по задаче используют тот же префикс в имени файла и заголовке,
например `docs/1.4_OWNERSHIP_CONVENTIONS.md`. Несколько документов одной задачи
сохраняют общий префикс, как карта API и её полный перечень для 1.1.
Критерии готовности и контрольные точки не являются отдельными задачами.

Порядок зависимостей: **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8**.

Каждая фаза должна оставлять проект собираемым. Исправления поведения и
механические переносы файлов оформлять отдельными коммитами. Регрессионные тесты
на исправленное поведение включать вместе с исправлениями, чтобы промежуточные
коммиты не оставляли обязательные проверки падающими.
